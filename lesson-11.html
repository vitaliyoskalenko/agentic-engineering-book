01

Чому harnessТа сама модель — різні результати

Документація Claude Code визначає термін так: Claude Code — це шар навколо моделі, який дає їй інструменти і керує контекстом, який вона бачить; цей шар і називають agentic harness. У статтях про бенчмарки той самий шар називають scaffold. Що він важить стільки ж, скільки модель, видно з першоджерел:

ДжерелоЩо показано про harness
«Building effective agents», 19.12.2024Готуючи агента для SWE-bench, команда Anthropic більше часу оптимізувала інструменти, ніж загальний промпт. Модель плуталася у відносних шляхах, коли виходила з кореня репозиторію; після того як інструмент почав вимагати абсолютний шлях, помилки зникли.
«Raising the bar on SWE-bench Verified», 06.01.2025Агент = модель + scaffold. Мінімальний scaffold — промпт, Bash і Edit — дав Claude 3.5 Sonnet 49% проти попереднього рекорду 45%. Open source і стартапи «сильно підвищували результат навколо тієї самої моделі», оптимізуючи scaffold.
Анонс Claude Sonnet 4.5, 29.09.202577,2% на SWE-bench Verified отримано з простим scaffold (bash і редагування заміною рядків) і доданим до промпту реченням: «використовуй інструменти якомога більше, в ідеалі понад 100 разів». Цифра бенчмарку описує пару «модель + harness», а не модель.
«Writing effective tools for agents», 11.09.2025Навіть невеликі правки описів інструментів дають помітний приріст; більше інструментів не означає кращий результат. Claude Code типово обрізає відповідь інструмента до 25 тис. токенів.
«Effective harnesses for long-running agents», 26.11.2025Агент на Agent SDK з Opus 4.5 будує застосунок на 200+ фіч у багатьох контекстних вікнах. Без додаткових шарів він або намагався зробити все одразу, або оголошував роботу готовою зарано. Допомогли агент-ініціалізатор, файл прогресу, список фіч у JSON (модель рідше переписує JSON, ніж Markdown) і git.
Архітектура

У статті про довгі задачі обидва агенти мали однакові системний промпт, інструменти й harness і відрізнялися лише першим повідомленням. Найдешевший шар для зміни поведінки — той, що ближче до задачі: повідомлення і файли в робочій теці, а не переписаний harness.

03

Harness Claude Code ззовніЩо видно без доступу до коду

Перша подія потоку stream-json — system/init: модель, режим дозволів, інструменти, MCP-сервери, skills, плагіни. Це опис harness, яким він зібрався саме для цього запуску. Порівняємо робочу конфігурацію з ізольованою:

init — лише кількості
$ claude -p "Відповідай одним словом: ок" --model haiku --output-format stream-json --verbose

result: 'ок' · input 37 312 токенів · total_cost_usd 0.00336

$ claude -p "Відповідай одним словом: ок" --model haiku --setting-sources project --strict-mcp-config --tools "Read,Grep" --output-format stream-json --verbose

result: 'ок' · input 6 176 токенів · total_cost_usd 0.00124
реальний вивід · Claude Code 2.1.299 · claude-haiku-5-5 · 14.10.2026 · підраховано з події system/init і result; назви MCP-серверів, skills і плагінів не публікуються
  • Одне слово «ок» коштувало 37 тис. токенів входу з робочою конфігурацією і 6 тис. з двома інструментами. Сім MCP-серверів і десятки skills — це шари harness, за які ви платите на кожному запиті, навіть коли вони не потрібні.
  • --setting-sources project не читає ваші особисті ~/.claude/settings.json (у робочій конфігурації там легко набирається тисяча правил allow, а стартовий режим — auto, як і видно з першого запуску), --strict-mcp-config не підключає MCP-сервери, крім переданих через --mcp-config. Для відтворюваних запусків, демо і CI — обидва. Але в чужому репозиторії це пастка: project вимикає ваші налаштування, а налаштування самого репозиторію (його хуки й env) вмикає, і в режимі -p вони спрацьовують ще до відповіді моделі. Для незнайомого коду — --setting-sources user або disableAllHooks (урок 3.4).
  • У типовому наборі на macOS немає Grep і Glob — Claude Code шукає через Bash; це записано і в довідці --tools. Назвіть їх явно, якщо Bash вимкнено.

04

Системний промпт агентаЗамінити чи доповнити

Системний промпт агента — не «будь корисним асистентом», а інструкція до harness: хто відповідає, на якій поверхні, що вважати безпечним, як користуватися інструментами. У Claude Code чотири прапорці, і всі працюють в інтерактивному й неінтерактивному режимі:

ПрапорецьЩо робитьКоли
--append-system-prompt, …-fileДописує текст у кінець типового промпту; настанови щодо інструментів і безпеки лишаютьсяАгент лишається coding-асистентом з вашими правилами: формат звіту, домен, стиль
--system-prompt, --system-prompt-fileЗамінює весь промпт; від типового не лишається нічогоІнша роль, поверхня або модель дозволів: агент у конвеєрі, на який ніхто не дивиться

Перевіримо, що змінює кожен варіант. У теці лежить CLAUDE.md з одним правилом: кожну відповідь закінчувати рядком «— lectern-ok». Питання однакове: «Хто ти і для чого тебе тут запущено?».

реальні відповіді · Claude Code 2.1.299 · claude-haiku-5-5 · 14.10.2026 · три окремі запуски, відповіді скорочено
  1. CLAUDE.md діє і з заміненим промптом. Claude Code доставляє його системним нагадуванням у розмові, а не в системному промпті. Заміна промпту не «вимикає проєкт»: щоб агент не бачив CLAUDE.md, приберіть джерело налаштувань (--setting-sources) або запускайте з --bare.
  2. Заміна прибирає більше, ніж роль. Вхід зменшився в 3,6 раза (у /context системний промпт — з 3,2 тис. до 169 токенів), а з ним зникли настанови щодо інструментів, безпеки й нагадувань. Документація радить: у власному промпті одним реченням пояснити, що системні нагадування — це контекст від застосунку, а не прохання користувача. Інструкції для комітів залишаються, бо вони в описі інструмента Bash, а не в промпті.
  3. Заміна ламає спільний кеш. Типовий промпт однаковий у всіх сесіях, тож він приходив з кешу (3 429 токенів). Власний на першому запиті записується в кеш заново. Для статичної частини власного промпту є маркер __SYSTEM_PROMPT_DYNAMIC_BOUNDARY__: усе вище нього кешується окремо від змінної частини.
Пастка Agent SDK

Без параметра system_prompt Agent SDK бере мінімальний промпт: лише підтримку виклику інструментів, без безпекових настанов Claude Code. claude -p натомість типово бере повний промпт Claude Code. Скрипт, перенесений з CLI в SDK «один до одного», поводиться інакше, доки ви не вкажете пресет claude_code. Деталі API — урок 2.5.

--bare: harness без автовиявлення

Режим --bare не шукає хуки, skills, плагіни, MCP-сервери, auto memory і CLAUDE.md, не надсилає системних нагадувань і не запускає фонових задач. Модель отримує Bash, читання і редагування файлів, а решту harness ви передаєте явно: --append-system-prompt-file, --settings, --mcp-config, --agents. Автентифікація — лише ANTHROPIC_API_KEY або apiKeyHelper, без входу через підписку.

zsh — CI
$ claude --bare -p "Summarize README.md" --allowedTools "Read"
команда з офіційної документації Claude Code · не запускалась у цьому уроці: потрібен ANTHROPIC_API_KEY

За документацією, --bare — рекомендований режим для скриптів і SDK, і в майбутньому він стане типовим для -p. Без нього claude -p виконує хуки з .claude/settings.json і підключає сервери з .mcp.json навіть у теці, якій ви не довіряли.

05

Інструменти і дозволиЩо існує, що виконується, що заборонено

Три прапорці легко сплутати, бо всі приймають назви інструментів. Вони працюють на різних шарах:

ПрапорецьШарЕфект
--tools "Read,Bash"Набір інструментівМодель бачить лише ці вбудовані інструменти; решти для неї не існує. На MCP не впливає — для них --disallowedTools "mcp__*"
--allowedTools "Bash(git diff *)"Дозволи · allowЦі виклики виконуються без запиту; решта йде за режимом. Нічого не прибирає з контексту
--disallowedTools "Bash(rm *)"Дозволи · denyВиклик, що збігся, відхиляється. Голе ім'я ("Edit") прибирає інструмент із контексту, правило з дужками лишає інструмент і відхиляє лише збіги

Як читаються правила

Правила перевіряються в порядку deny → ask → allow, перше спрацювання вирішує, і конкретність правила порядку не змінює. Широкий deny Bash(aws *) блокує і aws s3 ls, навіть якщо для нього є окремий allow. Те саме між рівнями налаштувань: deny у налаштуваннях користувача блокує allow проєкту, а керований (managed) deny не скасовує навіть --allowedTools з командного рядка.

ПравилоЗбігаєтьсяНе збігається
Bash(npm run build)лише npm run buildnpm run build --watch
Bash(git diff *)git diff, git diff --statgit diff-index: пробіл перед * — частина правила
Bash(ls*)ls -la, але й lsof—
Bash(git * main)git push origin main і git -c core.fsmonitor=<script> diff maingit log
Read(./.env), Edit(src/**)шлях відносно теки проєкту; // — абсолютний, ~/ — домашнійRead-deny діє і на Edit/Write того самого шляху
WebFetch(domain:github.com)завантаження з цього доменуcurl у Bash — це інший інструмент

Claude Code розбирає складені команди: Bash(safe-cmd *) не дозволить safe-cmd && other-cmd, кожна частина має збігтися окремо, а deny спрацьовує на будь-якій частині, зокрема в підоболонці чи $(…). Перед порівнянням знімаються обгортки timeout, nice, nohup та кілька інших, тож Bash(npm test *) збігається з timeout 30 npm test.

Пряма вказівка для обходу не обов'язкова. В іншому запуску з тим самим blocklist і промптом «якщо команду заблоковано, знайди інший спосіб» модель після відмови для rm сама перейшла на python3 -c … os.unlink і видалила файл. У наступному запуску, де обхідні команди були перелічені прямо, вона відмовилася обходити заборону. Поведінка моделі змінюється від запуску до запуску, тому межа має триматися без її згоди.

Чому allowlist, а не blocklist

Deny-правило зіставляється з текстом команди, а не з програмою: документація прямо пише, що Bash(rm *) не зупиняє /bin/rm чи bash -c 'rm …', а Bash(git push *) — git -C . push. Способів зробити небажане необмежено, тому список заборон завжди неповний. Allowlist перелічує скінченну множину того, що потрібно задачі, а все інше за замовчуванням стає запитом або відмовою. Deny лишається для того, що не має статися ніколи навіть за широкого allow (Read(./.env), Bash(git push *)), а межа, яка не залежить від тексту команди, — це sandbox.

Те саме в трьох інструментах

{
  "permissions": {
    "allow": ["Bash(python3 -m pytest *)", "Bash(git diff *)", "Edit(src/**)"],
    "ask":   ["Bash(git push *)"],
    "deny":  ["Read(./.env)", "Read(./secrets/**)"]
  },
  "sandbox": { "enabled": true, "allowUnsandboxedCommands": false }
}

.claude/settings.json проєкту. Allow-правила і додаткові теки з цього файлу діють лише після того, як ви прийняли діалог довіри до теки; deny й ask — одразу.

Codex розділяє дві осі. Пісочниця (--sandbox, sandbox_mode): read-only; workspace-write — читання, редагування й команди в робочій теці, типовий для тек під git; danger-full-access — без пісочниці. Політика схвалень (--ask-for-approval, -a): on-request питає перед редагуванням поза робочою текою і мережевими командами, never не питає, але межі пісочниці лишаються; untrusted більше не підтримується. Мережа типово вимкнена; механізм — Seatbelt на macOS, bwrap і seccomp у Linux.

sandbox_mode = "workspace-write"
approval_policy = "on-request"

[sandbox_workspace_write]
network_access = false

з офіційної документації Codex · не запускалось у цьому уроці

SandboxМежа, яку ставить операційна система

Дозволи вирішують, чи запустити команду. Sandbox вирішує, що запущений процес зможе зробити, і застосовується до Bash, PowerShell, Monitor та всіх дочірніх процесів. На macOS він побудований на Seatbelt, у Linux і WSL2 — на bubblewrap і socat; типово вимкнений, вмикається /sandbox або "sandbox": {"enabled": true}. Перевіримо пробами з документації, дозволивши Bash цілком, щоб дозволи нічого не блокували:

Запис за межами робочої теки і пряме з'єднання з мережею заблокувала ОС, а не правило. Зверніть увагу на порожній permission_denials: відмови sandbox — це помилки команд, а не відмови дозволів, тож монітор, який дивиться лише на це поле, їх не побачить.

  • Потрібні обидві ізоляції. Anthropic пояснює: без мережевої скомпрометований агент вивантажить SSH-ключі, які може прочитати; без файлової — вийде з пісочниці й отримає мережу. Типове читання ~/.ssh тримається лише на тому, що мережа закрита.
  • Sandbox прибирає втому від запитів. За внутрішніми даними Anthropic (20.10.2025), він зменшив кількість запитів дозволів на 84%: команда в межах пісочниці виконується без питань, бо найгірше, що вона може, обмежене ОС. Людина, яка схвалює сотий запит, уже не читає, що схвалює.
  • Що лишається поза ним. Вбудовані Read, Edit, WebFetch підкоряються лише дозволам (denyRead не зупиняє Read, allowedDomains не обмежує WebFetch); хуки, локальні MCP-сервери й LSP працюють з вашими повними правами. Щоб усе було за однією межею, сам Claude Code запускають у контейнері чи віртуальній машині.
  • Аварійний вихід. Команду, що впала в пісочниці, модель може попросити повторити без неї (параметр dangerouslyDisableSandbox). Allow-правило, яке збігається з командою, схвалює і такий повтор без запиту. "allowUnsandboxedCommands": false вимикає цей вихід зовсім.

Lectern · крок 2.3

Генератор квізу з однієї лекції. Специфікація лежить поруч із кодом, щоб будь-хто бачив, з чим агент запускається (обґрунтування кожного рядка — у чеклісті вище):

# Lectern · harness v0
Промпт: prompts/system.md, 12 рядків,
  ЗАМІНЮЄ типовий (--system-prompt-file)
Інструменти: Read; без Bash, Edit,
  WebFetch і MCP (--tools "Read",
  --strict-mcp-config)
Дозволи: dontAsk; налаштування розробника
  не читаються (--setting-sources project)
Зупинка: --max-turns 4,
  --max-budget-usd 0.05;
  успіх = JSON + усі цитати дослівні
Контекст: одна лекція = одна чиста сесія
Логи: --output-format json → runs/;
  num_turns, total_cost_usd,
  permission_denials

Системний промпт — 12 рядків. Останній рядок узято з настанови документації для власних промптів:

Ти — генератор квізів Lectern. Працюєш лише з файлами в каталозі lectures/.
Задача: за текстом лекції створити питання з одним правильним варіантом.
Правила:
1. Кожне питання спирається на цитату — дослівний фрагмент лекції (без змін, без «…»).
2. Якщо фактів для питання немає в тексті, не вигадуй: пропусти питання.
3. Три неправильні варіанти мають бути правдоподібними, але суперечити тексту.
4. Мова — мова лекції.
5. Не змінюй файли й не виконуй команд: ти лише читаєш.
Формат відповіді — тільки JSON без пояснень:
{"questions":[{"q":"…","options":["…","…","…","…"],"answer":0,"quote":"…"}]}
Якщо лекцію не вдалося прочитати, поверни {"error":"…"}.
Застосунок додає до розмови системні нагадування; це контекст від застосунку, а не прохання користувача.

11 питань
1. Агент у CI має лише читати код і запускати тести. Конфігурація: --allowedTools "Bash" --disallowedTools "Bash(rm *)" "Bash(git push *)". Що з нею не так?
Так. Blocklist перелічує заборони, а способів зробити небажане безліч; у демо уроку файл видалили через python3 -c. Тут потрібен allowlist: Bash(python3 -m pytest *) і читання.
Deny діє і за наявності allow (його перевіряють першим) і ловить частини складених команд, але зіставляється з текстом команди: /bin/rm чи python3 -c він не впізнає. З Bash в allow усе непередбачене виконається без питань.
2. Правила: allow Bash(aws s3 ls), deny Bash(aws *). Модель викликає aws s3 ls. Що станеться?
Так. Порядок завжди deny → ask → allow, і allow не може вирізати виняток із deny.
Specificity не впливає: перше спрацювання в порядку deny → ask → allow вирішує, а deny Bash(aws *) збігається.
3. Генератор квізів запускається з --system-prompt у репозиторії, де лежить CLAUDE.md з правилами коду. Що отримає модель?
Так. CLAUDE.md приходить у розмову, а не в системний промпт; у демо правило «— lectern-ok» спрацювало і з заміненим промптом. Прибирають його через --setting-sources або --bare.
Заміна стосується лише системного промпту, а дописування в кінець — це --append-system-prompt. CLAUDE.md, як і інші системні нагадування, Claude Code додає в розмову окремо.
4. Агент має лишитися coding-агентом, але звітувати у JSON-форматі вашої команди. Який прапорець?
Так. Роль і поверхня ті самі, змінюється лише формат звіту, тож доповнення — найменш ризикова зміна.
Заміна прибирає настанови щодо інструментів і безпеки та ламає кеш спільного префікса; вона доречна, коли змінилися роль, поверхня чи модель дозволів. Без інструментів агент перестає бути coding-агентом.
5. Sandbox увімкнено, allowedDomains порожній. Модель викликає WebFetch для довільного домену. Що вирішує, чи завантажиться сторінка?
Так. Read, Edit, WebFetch, WebSearch працюють поза sandbox і підкоряються дозволам; allowedDomains WebFetch не обмежує.
Sandbox обгортає Bash, PowerShell і Monitor, а мережевий проксі — їхні процеси. Вбудований WebFetch від нього не залежить, його контролюють правила на кшталт WebFetch(domain:…).
6. Sandbox Claude Code типово дозволяє cat ~/.ssh/id_rsa. Що тримає це в безпеці і що зламає захист?
Так. Тому Anthropic і наголошує, що потрібні обидві ізоляції: файлова і мережева. Секрети варто ще й закрити denyRead.
Типове читання охоплює майже всю машину, зокрема ~/.ssh, а секретів sandbox сам не ховає — навіть змінні середовища успадковуються. Безпеку дає закрита мережа, тож її розширення — ризик.
7. Монітор CI сповіщає, коли permission_denials не порожній. Агент у sandbox тричі отримав «Operation not permitted». Що побачить монітор?
Так. У пробі sandbox з уроку дві команди впали, а permission_denials лишився порожнім. Дивіться ще на is_error результатів інструментів.
permission_denials заповнює шар дозволів. Sandbox блокує вже запущену команду на рівні ОС, і це видно лише як помилку в результаті інструмента.
8. Треба порахувати рядки ERROR у логу на мільйон рядків, а в агента лише Read. Чого очікувати?
Так. На 3000 рядках різниця вже була 6,4 раза за вартістю; на мільйоні рядків файл не влізе навіть у вікно на 1 млн токенів.
Read повертає вміст, а не результат обчислення. Набір інструментів визначає, що потрапляє в контекст і скільки це коштує.
9. Ваш скрипт з claude -p у колеги поводиться інакше: інші запити дозволів, інші MCP-інструменти. Як зробити запуск відтворюваним?
Так. Без них -p підтягує особисті налаштування, плагіни й MCP-сервери машини, на якій запущений.
Прохання в промпті не прибирає інструменти з контексту, а bypass лише вимикає перевірки. Відтворюваність дає явно заданий harness.
10. Агентові потрібні npm test, git diff і редагування src/. Який набір правил найкращий?
Так. Скінченний allowlist під задачу, deny — для того, що не має статися ніколи.
Blocklist пропускає все непередбачене, а широкі npm * і git * разом з acceptEdits дозволяють і git push, і правки поза src/. Потрібен скінченний allowlist під задачу; bypass документація радить лише для ізольованих контейнерів і VM.
11. Скрипт перенесли з claude -p в Agent SDK, не вказавши system_prompt. Що змінилося в harness?
Так. Це прямо записано в документації SDK: типовий промпт -p і SDK різні.
Інфраструктура та сама, але типовий системний промпт ні: claude -p бере повний промпт Claude Code, а SDK без параметра — мінімальний, лише з підтримкою виклику інструментів.

ТермінКоротко

пріоритет deny (deny-first)Правила перевіряються в порядку deny → ask → allow; перше спрацювання вирішує.
blocklist (deny-список)Широкий allow плюс перелік заборон; не межа, бо зіставляється з текстом команди.

system/initПерша подія stream-json: модель, режим дозволів, інструменти, MCP, skills, плагіни запуску.
