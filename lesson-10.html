Agentic loop: observe → think → act → repeat; критерії зупинки

Агент — це модель, яку ваш код знову й знову викликає з наростаючою історією, доки щось не скаже «досить». Розбираємо цикл рядок за рядком, усі значення stop_reason і те, як спроєктувати зупинку, щоб агент не крутився вічно, не здавався зарано і не «чинив» тести замість коду.

Від моделі до агента≈ 55 хв12 картокперевірено 14.10.2026

Зазвичай це просто LLM, які користуються інструментами, спираючись на зворотний зв'язок від середовища, у циклі.

Після уроку ви зможете

  • написати agentic loop на Messages API і показати в кожному рядку фази observe, think і act;
  • обробити кожне значення stop_reason, а не лише tool_use;
  • спроєктувати критерії зупинки: виконано, бюджет, застій, ескалація — і хто з них вирішує;
  • обмежити прогін у Claude Code через --max-turns і --max-budget-usd і прочитати subtype результату;
  • розпізнати шість типових збоїв циклу і поставити перевірку поза моделлю;
  • реалізувати й протестувати StopPolicy для агента-генератора Lectern.
01

Цикл у кодіТри десятки рядків між моделлю й агентом

Модель сама нічого не виконує. Вона повертає текст і, можливо, блоки tool_use — «виконай run з таким аргументом». Агентом її робить цикл у вашому коді: виконати запитане, дописати результат в історію, викликати модель ще раз. Мінімальна версія на Python SDK:

import subprocess

TOOLS = [{
    "name": "run",
    "description": "Виконує shell-команду в корені репозиторію "
                   "і повертає вивід.",
    "input_schema": {
        "type": "object",
        "properties": {"cmd": {"type": "string"}},
        "required": ["cmd"],
    },
}]


def run_tool(args):
    p = subprocess.run(args["cmd"], shell=True, capture_output=True,
                       text=True, timeout=60)
    out = (p.stdout + p.stderr)[-4000:]   # хвіст виводу, не весь лог
    return out, p.returncode != 0


def agent(client, task, max_turns=15):
    messages = [{"role": "user", "content": task}]
    for turn in range(1, max_turns + 1):
        resp = client.messages.create(model="claude-haiku-5-5", max_tokens=8000,
                                      tools=TOOLS, messages=messages)
        messages.append({"role": "assistant", "content": resp.content})
        if resp.stop_reason != "tool_use":
            return resp.stop_reason, turn, messages
        results = []
        for block in resp.content:
            if block.type == "tool_use":
                out, failed = run_tool(block.input)
                results.append({"type": "tool_result", "tool_use_id": block.id,
                                "content": out, "is_error": failed})
        messages.append({"role": "user", "content": results})
    return "max_turns", max_turns, messages

Наш код · з реальним API не запускався (у середовищі уроку немає ключа API). Логіку циклу перевірено підставним клієнтом із заготовленими відповідями: історія росте 1 → 3 → 5 повідомлень, ліміт обриває цикл на другому ході, команда з ненульовим кодом повертається з is_error: true. Shell без обмежень тут лише для наочності; дозволи — урок 2.3.

ФазаРядокЩо відбувається і де пастка
thinkclient.messages.create(…, messages=messages)Модель отримує всю історію і вирішує: відповісти текстом чи попросити інструмент. Це єдине місце, де «думає» модель; решта — ваш детермінований код.
вихідif resp.stop_reason != "tool_use"Модель «зупиняє» цикл лише тим, що не просить інструментів. Ця гілка однаково ловить успіх, відмову й обрізану відповідь — далі розберемо, чому так не можна лишати.
actrun_tool(block.input)Побічні ефекти стаються тут, у вашому процесі. Саме сюди ставлять дозволи, sandbox і timeout.
observetool_result з tool_use_id і is_errorМодель бачить світ лише через цей рядок. Що ви сюди поклали — те вона й «знає». 4000 символів хвоста замість усього логу — перший захист від роздування контексту.
repeatfor turn in range(…)Зовнішній запобіжник. У документації цикл написано як while True; у продакшні так лишати не можна.

Скільки коштує кожне «repeat»

API не має пам'яті між запитами (урок 1.3), тож кожна ітерація додає два повідомлення — відповідь моделі й результати інструментів — і наступний виклик несе їх усі. Справжні виміри з прогону Claude Code нижче: контекст кожного з п'яти викликів моделі.

Архітектура

Вартість ітерації ≈ розмір префікса + накопичена історія. Тому дешевий агент — це не «мало ітерацій», а короткі спостереження і стабільний префікс: тоді кеш тримає ~90% входу (урок 1.5), а історія росте на кілобайти, а не на мегабайти логів.

02

stop_reasonСім причин, з яких модель замовкла

Кожна відповідь Messages API несе stop_reason. Для циклу це перемикач: одне значення означає «продовжуй», інші — шість різних «стоп», і кожне треба обробити окремо.

stop_reasonЩо сталосяЩо робить цикл
tool_useМодель просить інструментиВиконати всі блоки tool_use, повернути tool_result, викликати знову
end_turnМодель закінчила відповідь самаВийти з циклу і передати результат верифікатору: це «модель вважає, що закінчила», а не «задачу виконано»
max_tokensВихід уперся в max_tokensЯкщо останній блок — недописаний tool_use, не виконувати його, а повторити запит з більшим max_tokens. Якщо обрізано текст — продовжити або підняти ліміт
stop_sequenceМодель видала один із ваших stop_sequencesОчікуваний кінець за вашим маркером; значення маркера — у полі stop_sequence
pause_turnСерверний цикл інструментів (наприклад, web search) вичерпав ліміт ітерацій — типово 10 на запитНадіслати відповідь назад як є: сервер продовжить
refusalМодель відмовилась. Це звичайна відповідь HTTP 200, не помилка; категорія — у stop_detailsНе повторювати той самий запит. Для Opus 5.5 і 5, Sonnet 5.5, Haiku 5.5, Fable 5 і 5.1 документація радить повтор на іншій моделі Claude; інакше — ескалація
model_context_window_exceededВідповідь заповнила контекстне вікноВважати відповідь обрізаною; стиснути або очистити історію (урок 1.3)

Восьме значення, compaction, з'являється лише з beta-компакцією і pause_after_compaction (урок 1.3).

Пастка з документації

Цикл виду if stop_reason == "tool_use": … else: return response повертає однаково і завершену відповідь, і відмову, і обрізаний посеред речення текст. Код, що після нього пише «готово», звітує про успіх у трьох різних ситуаціях. Розгалужуйте за кожним значенням.

Ще одна пастка: модель іноді повертає порожню відповідь (2–3 токени) з end_turn одразу після результатів інструментів. Документація називає дві причини: текстовий блок у тому ж повідомленні одразу після tool_result і повернення завершеної відповіді моделі без нічого нового. Ліки: результати інструментів — окремим повідомленням без тексту; порожню відповідь не повторювати без змін.

num_turns у результаті — лічильник Claude Code, не кількість викликів API: 5 викликів → num_turns 8; у простішому варіанті тієї ж задачі 4 виклики → 7. Ліміт --max-turns рахує інакше (нижче). Якщо число важливе для бюджету, рахуйте виклики самі за унікальними message.id у потоці.

Що ми перевірили самі

Тести запустили окремо — 7 з 7. git diff --quiet -- test_quotes.py lecture.txt — без змін, отже агент не «полагодив» тести. Але в diff є рядок text.replace("­", ""): на рев'ю він виглядає як заміна порожнього рядка порожнім, бо в лапках стоїть невидимий U+00AD. Вимога до правки — "\u00ad". «Готово» було правдою, і все одно рев'ю знайшло, що виправити.

04

Критерії зупинкиХто вирішує, що досить

Модель закінчує хід, коли вважає, що закінчила. Цього мало з двох боків: вона може вважати так зарано, а може не вважати ніколи. Anthropic формулює обидві половини правила так:

Під час виконання агентові критично важливо на кожному кроці отримувати від середовища «ground truth» (результати викликів інструментів чи виконання коду), щоб оцінювати прогрес. […] Задача часто закінчується після виконання, але поширено й додавати умови зупинки (наприклад, максимальну кількість ітерацій), щоб зберігати контроль.

“During execution, it's crucial for the agents to gain “ground truth” from the environment at each step (such as tool call results or code execution) to assess its progress. […] The task often terminates upon completion, but it’s also common to include stopping conditions (such as a maximum number of iterations) to maintain control.”

Anthropic, «Building effective agents», 19.12.2024

Done-tool: явний сигнал завершення

end_turn — неявний сигнал: модель закінчує хід і тоді, коли все зробила, і тоді, коли ставить уточнювальне питання, і тоді, коли ввічливо здається. Явніший спосіб — дати агентові інструмент завершення, наприклад submit_lecture(lecture), у якого input_schema — це схема готового результату. Тоді «готово» стає структурованою заявою, яку harness може відхилити: перевірка не пройшла — tool_result з is_error: true і переліком проблем, модель працює далі. Цикл закінчується лише тоді, коли done-tool викликано і перевірка пройшла.

Звідки брати числа

Ліміти ставте за вимірами, а не навмання. Наш прогін зробив 5 викликів, а --max-turns 2 нижче гарантовано його обриває. Робоче правило: прогнати 10–20 типових задач і поставити ліміт трохи вище за найдовший успішний прогін. Ліміт нижче за медіану перетворює успіхи на error_max_turns, а ліміт «про всяк випадок 200» нічого не захищає.

  • --max-turns немає в --help, але він задокументований: довідка CLI прямо каже, що --help показує не всі прапорці. Працює лише з -p, типово ліміту немає.
  • Ліміт рахує ходи з інструментами. За --max-turns 2 відбулося два виклики моделі, обидва з tool_use, і третього вже не було. num_turns при цьому показав 3, а stop_reason у результаті — tool_use: остання відповідь ще чекала інструментів.
  • Перший хід згорів на орієнтацію. Агент почав зі складеної команди cd … || cd …, harness її відхилив («Multiple directory changes in one command require approval for clarity»), і до тестів справа не дійшла. Тісний ліміт карає за кожен невдалий хід.
  • Бюджет перевищено на 5,7%. Claude Code порівнює витрати з лімітом після відповіді, тож відповідь, що перейшла межу, усе одно оплачено. Документація попереджає: витрати можуть перевищити ліміт на вартість однієї відповіді плюс те, що встигнуть витратити запущені субагенти. І це клієнтська оцінка, а не рахунок.
  • Код виходу 1 і немає поля result. Скрипт мусить читати subtype, а не шукати текст відповіді. Тут обидва прогони обірвались до будь-якої правки; обрив посеред редагування лишає напівзміну, тож коміт перед запуском (урок 0.3) — частина критеріїв зупинки.

Наскрізний проєктLectern: StopPolicy для агента-генератора

Lectern · крок 2.2

Агент Lectern (урок 2.5) читатиме PDF-лекцію і збиратиме урок: розділи, квіз, цитати. Сьогодні — правила, за якими він зупиняється. Їх пишемо до агента, бо від них залежить, що вважати успіхом. Чотири критерії з таблиці вище:

  • виконано — схема уроку валідна і кожна цитата знайдена в тексті лекції через check_quote. Це та сама функція, яку агент щойно полагодив, тож верифікатор уже покритий тестами;
  • бюджет — 12 ходів, $0,50 і 10 хвилин на лекцію. $0,50 — приблизно вдвічі більше за оцінку з уроку 1.5: $2,66 за курс з 10 лекцій, тобто ≈ $0,27 на лекцію. Це стартові числа, їх перевіримо вимірами в 2.5;
  • застій — та сама дія з тими самими аргументами або та сама помилка 3 рази поспіль;
  • ескалація — третя поспіль заява «готово», яка не пройшла перевірку.
"""Lectern: коли агентові-генератору лекції зупинитися."""
import json
import time
from dataclasses import dataclass

from quotes import check_quote

REQUIRED = {"title": str, "sections": list, "quiz": list, "quotes": list}


@dataclass(frozen=True)
class Verdict:
    stop: bool
    outcome: str  # continue | done | budget | stuck | escalate
    reason: str = ""


class StopPolicy:
    def __init__(self, max_turns=12, max_usd=0.50, max_seconds=600,
                 max_repeats=3, max_failed_checks=3, clock=time.monotonic):
        self.max_turns, self.max_usd, self.max_seconds = max_turns, max_usd, max_seconds
        self.max_repeats, self.max_failed_checks = max_repeats, max_failed_checks
        self.clock, self.started = clock, clock()
        self.turns, self.usd, self.failed_checks = 0, 0.0, 0
        self.last_key, self.repeats = None, 0
        self.last_error, self.same_error = None, 0

    def after_turn(self, tool, args, cost_usd, error=None):
        """Викликати після кожного ходу з викликом інструмента."""
        self.turns += 1
        self.usd += cost_usd
        key = (tool, json.dumps(args, sort_keys=True, ensure_ascii=False))
        self.repeats = self.repeats + 1 if key == self.last_key else 1
        self.last_key = key
        self.same_error = self.same_error + 1 if error and error == self.last_error else int(bool(error))
        self.last_error = error
        if self.repeats >= self.max_repeats:
            return Verdict(True, "stuck", f"{tool} з тими самими аргументами {self.repeats} рази поспіль")
        if self.same_error >= self.max_repeats:
            return Verdict(True, "stuck", f"та сама помилка {self.same_error} рази: {error[:80]}")
        if self.usd >= self.max_usd:
            return Verdict(True, "budget", f"${self.usd:.2f} із ${self.max_usd:.2f}")
        if self.turns >= self.max_turns:
            return Verdict(True, "budget", f"{self.turns} ходів із {self.max_turns}")
        if self.clock() - self.started >= self.max_seconds:
            return Verdict(True, "budget", f"понад {self.max_seconds} с")
        return Verdict(False, "continue")

    def on_done_claim(self, lecture, source):
        """Модель каже «готово». Перевіряємо самі: схема і кожна цитата."""
        problems = [f"поле {k}: потрібен {t.__name__}" for k, t in REQUIRED.items()
                    if not isinstance(lecture.get(k), t)]
        problems += [f"цитати немає в джерелі: «{q[:60]}»" for q in lecture.get("quotes") or []
                     if not check_quote(source, q)]
        if not problems:
            return Verdict(True, "done")
        self.failed_checks += 1
        if self.failed_checks >= self.max_failed_checks:
            return Verdict(True, "escalate", "; ".join(problems))
        return Verdict(False, "continue", "; ".join(problems))  # reason іде моделі як tool_result

Порядок перевірок навмисний: застій перевіряється до бюджету, тож людина побачить «read_pdf 3 рази поспіль», а не безлике «12 ходів із 12». Провалена заява «готово» повертає моделі перелік проблем, а не лише «ні»: агентові є з чим працювати на наступній ітерації.

def test_third_failed_check_escalates_to_human(self):
    p, bad = StopPolicy(), dict(GOOD, quiz=None)
    outcomes = [p.on_done_claim(bad, SOURCE).outcome for _ in range(3)]
    self.assertEqual(outcomes, ["continue", "continue", "escalate"])

def test_same_error_with_different_args_is_stuck(self):
    p = StopPolicy()
    for page in (7, 8):
        p.after_turn("read_pdf", {"page": page}, 0.0, error="PDF is encrypted")
    self.assertEqual(p.after_turn("read_pdf", {"page": 9}, 0.0, error="PDF is encrypted").outcome, "stuck")

1. Ваш цикл отримав stop_reason: "max_tokens", і останній блок відповіді — tool_use з командою rm -rf build/. Що робити?
Так. Обрізаний блок tool_use недописаний: аргументи можуть бути неповні. Документація радить повторити запит з більшим лімітом.
Відповідь обрізано посеред блоку, тож аргументи можуть бути неповні, а виконувати недописану команду небезпечно. Продовження — рецепт для обрізаного тексту; для tool_use повторюють запит з більшим max_tokens.
2. Цикл написано як у документації: if stop_reason == "tool_use": … else: return response, а після нього скрипт пише в Slack «урок готовий». Що піде не так?
Так. Гілка else об'єднує шість різних зупинок. Розгалужуйте за значенням і перед «готово» запускайте верифікатор.
Цикл завершиться на будь-якому значенні, крім tool_use, pause_turn теж: else ловить і end_turn, і refusal, і max_tokens. Успіх — лише після перевірки результату.
3. Нічний CI-скрипт запускає claude -p … --max-turns 10 і бере текст з поля result. Сьогодні агентові забракло ходів. Що отримає скрипт?
Так, саме це показав наш прогін з --max-turns 2. Скрипт має читати subtype, а не шукати текст.
У реальному прогоні з --max-turns 2 результат мав error_max_turns, is_error: true, поля result не було, а процес вийшов з кодом 1.
4. Фінансист вимагає: «жоден прогін не дорожчий за $1,00». Ви ставите --max-budget-usd 1.00. Чи виконано вимогу?
Так. У нашому прогоні ліміт $0,004 дав $0,00423. Перевищення — до вартості однієї відповіді плюс витрати запущених субагентів, і це ще й клієнтська оцінка.
Відповідь, що перейшла межу, усе одно оплачено: ліміт $0,004 дав $0,00423, і субагентів у тому прогоні не було. Ставте ліміт із запасом.
5. Агент уже 6 разів поспіль запускає ті самі тести з тією самою помилкою ModuleNotFoundError: lxml. Бюджет ходів — 40. Що мало спрацювати?
Так. Бюджет — остання межа, а не детектор проблем. Тут потрібна людина: залежності немає, і агент не може її поставити.
Ліміт ходів спрацює лише після 40 марних ітерацій, а верифікатор лише знову поверне моделі ту саму помилку. Однакова помилка N разів — ознака застою, і тут бракує рішення людини.
6. Ви заборонили Edit(**/test_*.py). Агент створив fix.py, який відкриває test_quotes.py і переписує assert, і запустив його. Що це зловить?
Так. Deny-правила діють на вбудовані файлові інструменти і на файлові команди, які Claude Code розпізнає в Bash, але не на скрипт, що сам відкриває файл.
Документація прямо каже: Read- і Edit-правила діють на файлові команди, які Claude Code розпізнає в Bash, але не на Python-скрипт, що сам пише у файл. Ловить це лише перевірка результату поза моделлю або sandbox.
7. Генератор Lectern каже «готово», але 2 з 5 цитат не проходять check_quote. Це перша така заява. Що робить StopPolicy з уроку?
Так. Перелік проблем дає агентові конкретну роботу, а ліміт провалених перевірок не дає йому крутитися вічно.
Застій у StopPolicy — це повтор дій чи помилок, а «виконано» — це кожна цитата в джерелі. Перша невдача повертає агентові перелік проблем; ескалація — після трьох.
8. Навіщо давати агентові done-tool submit_lecture, якщо він і так закінчує хід з end_turn?
Так. end_turn буває і після уточнювального питання, і коли модель здається. Done-tool відділяє «ось результат» від «я замовк».
end_turn і max_tokens — різні значення, і зайвий виклик моделі тут нічого не вирішує. Цінність done-tool у тому, що заява про завершення має схему і її можна перевірити й відхилити через tool_result з is_error.
9. Після ітерацій набір тестів, що падають, такий: {A} → {B} → {A} → {B}. Ліміт ходів ще далеко. Що правильно?
Так. Повтор стану означає, що агент ходить по колу між двома правками. Потрібне рішення про компроміс між A і B.
Дії щоразу різні, тож детектор однакових дій мовчить, а ліміт ходів просто спалить бюджет. Ловіть повтор стану і віддавайте вибір людині.
10. Колега рахує вартість кроку агента як total_cost_usd / num_turns з результату Claude Code. Що не так?
Так. Для бюджету кроків рахуйте виклики самі за унікальними message.id у потоці stream-json.
Ми виміряли: 5 викликів → num_turns 8, 4 виклики → 7. Ділення дасть занижену ціну кроку.
11. Ваш Stop-хук у Claude Code повертає decision: "block", доки не пройде інтеграційний тест, але тестова база даних лежить. Що станеться?
Так. Ліміт у 8 продовжень поспіль скидається з кожним викликом інструмента, а агент, що перевіряє тест, саме їх і робить. Хук, який вимагає недосяжного, має перевіряти stop_hook_active і кликати людину.
Запобіжник у 8 продовжень обнуляється, щойно агент викликає інструмент, а stop_hook_active нічого не зупиняє сам — його має перевірити ваш хук. Без гілки «покликати людину» цикл крутитиметься до --max-turns чи бюджету.

Домашнє завданняДві задачі з AI-перевіркою

1. Критерії зупинки для власного агента

Оберіть агентну задачу зі своєї роботи і спроєктуйте для неї зупинку: таблицю «критерій → сигнал → хто вирішує → чим закінчується», числа лімітів з обґрунтуванням, детектор застою і правило ескалації, а також код або псевдокод перевірки «готово» поза моделлю з трьома тестовими сценаріями.

2. Розбір траси агента

Запустіть невелику задачу в claude -p --output-format stream-json --verbose (або візьміть трасу з тексту завдання), розкладіть її по викликах на observe, think і act, порахуйте ріст контексту і визначте, де спрацював би кожен критерій зупинки. Потім повторіть прогін з тісним --max-turns і опишіть результат.
