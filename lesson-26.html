Fine-tuning, prompting чи RAG: три способи адаптувати модель

Модель не знає ваших документів і не пише у вашому форматі: це можна виправити промптом, контекстом, пошуком, інструментами або донавчанням, і кожен спосіб змінює щось своє. 01

Чотири важелі і п'ятийЩо саме ви змінюєте

Модель відповідає погано з двох різних причин: не знає потрібних фактів (ваших лекцій, регламенту, цін) або не так поводиться (формат, стиль, тон, межі довжини). Важелі адаптації лікують різне, тому першим кроком є діагноз з eval-набору, а не вибір технології.

Звідси робоче правило: знання — у контекст, поведінка — у промпт, а ваги чіпають, коли промпт вичерпано. Для знань воно має пряме підтвердження. Ovadia et al. (2023) порівняли донавчання на текстах і RAG на однакових фактах: «unsupervised fine-tuning дає певне покращення, але RAG стабільно його перевершує», причому і для знань, які модель бачила під час навчання, і для зовсім нових. Автори зазначають, що нові факти модель засвоює з ваг лише тоді, коли бачить багато різних формулювань того самого факту, тобто для одного регламенту доведеться синтезувати сотні перефразувань.

Архітектура

Ще у статті, яка дала назву RAG (Lewis et al., травень 2020), сформульовано дві речі, яких не дають знання у вагах: джерело відповіді і оновлення знань без перенавчання. Для Lectern перше — це вимога точності цитат з уроку 0.2: факт з ваг неможливо перевірити за сторінкою PDF, факт з контексту — можна.

Отже, для актуальних моделей Claude (Haiku, Sonnet, Opus 5.5, Fable 5.1) публічного шляху змінити ваги немає. Адаптація зводиться до промпту, контексту, пошуку й інструментів. Якщо донавчання справді потрібне (мільйони однотипних класифікацій, жорсткий стиль на мінімумі токенів, модель на власному залізі), це означає іншу модель:

  • та сама сторінка Bedrock серед моделей для fine-tuning перелічує Amazon Nova і Meta Llama 3.1 / 3.2;
  • відкриті моделі донавчають на власному залізі. LoRA (Hu et al., 2021) навчає малі матриці поверх замороженої моделі: порівняно з повним донавчанням GPT-3 175B — у 10 000 разів менше параметрів для навчання, утричі менше пам'яті GPU, без додаткової затримки інференсу.

Ціна такого рішення: свій eval-набір, підготовлені дані, а з кожною новою базовою моделлю — повторне навчання. Промпт переноситься на нову модель за день, ваги — ні.

03

Експеримент 1: правила чи прикладиФлешкартка у форматі курсу

Поведінкова задача з цього ж курсу: за терміном написати картку у форматі cards.json. Haiku 5.5 у headless-режимі Claude Code, інструменти вимкнено, системний промпт власний. Шість термінів (rate limit, feature flag, canary-реліз, dead letter queue, semantic versioning, idempotency key), по два запуски, чотири варіанти системного промпту — 48 запусків:

  • zero — одне речення: «склади картку у форматі карток курсу: JSON з полями front, back, notes, examples, detail»;
  • rules — те саме + сім явних правил (лише JSON без ```, рівно п'ять полів, back з малої літери без крапки до 160 символів, notes до 90, два приклади, detail з 2–4 розділами ## );
  • few — одне речення + три справжні картки курсу в <examples>;
  • rules+few — правила і ті самі приклади.

Сім перевірок рахує код, а не модель. Окремо рахуємо маркер «домашнього стилю», про який правила мовчать: detail починається з ## Значення, як у двох з трьох прикладів.

def checks(term, out):
    try:
        c = json.loads(out)
    except ValueError:
        return {"json": False}
    ok = lambda f: isinstance(c.get(f), str) and c[f] != ""
    return {
        "json": True,
        "keys": set(c) == {"front", "back", "notes", "examples", "detail"},
        "front": c.get("front") == term,
        "back": ok("back") and c["back"][:1].islower() and not c["back"].endswith(".") and len(c["back"]) <= 160,
        "notes": ok("notes") and not c["notes"].endswith(".") and len(c["notes"]) <= 90,
        "examples": isinstance(c.get("examples"), list) and len(c["examples"]) == 2,
        "detail": ok("detail") and c["detail"].startswith("## ") and 2 <= c["detail"].count("## ") <= 4,
    }

Що це доводить і чого ні

12 запусків на умову, одна модель, одна задача: це не статистика, а приклад механізму. Він збігається з розподілом ролей: приклади задають стиль, правила задають межі, а код перевіряє межі. Конверт JSON надійніше закривають structured outputs (урок 2.1). Fine-tuning розв'язав би цю задачу тисячами карток і новим навчанням після кожної зміни стилю, а промпт розв'язав її за 2,5 тис. токенів.

Експеримент 2: увесь корпус чи RAGПоріг 200 тис. токенів на практиці

Поріг з епіграфа Anthropic супроводжує застереженням: prompt caching робить підхід «усе в промпт» «значно швидшим і дешевшим», але з ростом бази знань потрібне масштабованіше рішення. Перевіримо на корпусі, який модель не могла бачити під час навчання.

Корпус. Чотири лекції про вигадане озеро Світанок. Факти (глибини, дати, види, правила) написано вручну, прозу навколо них розгорнула Haiku 5.5 із забороною додавати нові факти; скрипт перевірив, що в тексті немає чисел поза списком фактів. Разом 33 908 символів, 14,5 тис. токенів, 38 розділів. Лекція 4 містить пастку: застарілу глибину 21 м з експедиції 1934 року.

Обидві умови отримують ту саму інструкцію: відповідати лише з матеріалів, а якщо відповіді немає — так і сказати. Long context кладе весь корпус у системний промпт, питання йде останнім, як радять docs для довгих документів. RAG віддає моделі три найкращі розділи за BM25. Увесь ретривер:

# Tiny keyword RAG: split lectures into "## " sections, rank with BM25, return top-k.
import glob, json, re, sys
from rank_bm25 import BM25Okapi

def tokenize(text, stem=False):
    words = re.findall(r"\w+", text.lower())
    return [w[:5] if stem else w for w in words]  # stem=True: crude prefix "stemming"

def load_chunks():
    chunks = []
    for path in sorted(glob.glob("L*.md")):
        lecture, *sections = open(path).read().split("\n## ")
        title = lecture.splitlines()[0].lstrip("# ")
        chunks += [{"lecture": title, "text": "## " + s.strip()} for s in sections]
    return chunks

def retrieve(query, k=3, stem=False):
    chunks = load_chunks()
    bm25 = BM25Okapi([tokenize(c["lecture"] + " " + c["text"], stem) for c in chunks])
    scores = bm25.get_scores(tokenize(query, stem))
    top = sorted(range(len(chunks)), key=lambda i: -scores[i])[:k]
    return [dict(chunks[i], score=round(float(scores[i]), 2)) for i in top]

  1. Q2 — розрив словника. У питанні «місяці», «рибалити», у тексті «нерестова заборона», «вилов», «з 1 квітня по 31 травня». Потрібний розділ — лише шостий у рейтингу, а першими йдуть розділи, де збіглися «озері», «на», «не». Грубий стемінг (перші 5 літер слова) не підняв його в топ-3. Модель чесно відповіла «У матеріалах цього немає», і це хибна відсутність: порожній пошук сказав «немає» про факт, який у корпусі є.
  2. Q4 — агрегація. Інвазійні види розкидані по трьох розділах; у топ-3 потрапили два. Відповідь: «В матеріалах згадано два інвазійні види». Вона впевнена, неповна і виглядає повною. Питання «перелічіть усі», «скільки разів», «порівняйте всі» — структурно слабке місце RAG з фіксованим k; для них потрібен увесь корпус, структурований індекс або агент, що шукає кілька разів.
  3. Top-8 виправив обидва за 4,1 тис. токенів, що все ще в 3,5 раза менше за корпус. Але k підібрано під п'ять відомих питань; на незнайомих гарантії немає.
  4. Q1 пройшов в обох умовах, хоча пастка з 21 м потрапила і в топ-3: лекція 4 сама каже, що значення застаріло. Розділ, вирваний без такого речення, дав би моделі дві «правди».

Висновок для корпусу до ~100–200 тис. токенів

Увесь корпус у кешованому промпті дав 10/10 відповідей, а кожне наступне питання коштувало менше, ніж RAG без кешу. RAG тут додав роботу (chunking, індекс, вибір k) і дві тихі помилки. Межа рухається від моделі: Haiku 5.5 за промпт понад 100 тис. токенів бере в 5 разів більше (урок 1.5), а context rot на сотнях тисяч токенів реальний (урок 1.3). Тому 200 тис. — це стеля, а не ціль: поріг перемикання міряють на власному eval-наборі.

05

Мінімум RAG для рішенняЧому пошук промахується і що дає Contextual Retrieval

Класичний конвеєр: розрізати документи на фрагменти (chunks), проіндексувати їх, на кожен запит знайти top-k і вставити в промпт. Індекс буває лексичний (BM25: збіг слів з урахуванням їхньої рідкісності й довжини фрагмента) або семантичний (embeddings, урок 1.2). Вони помиляються по-різному. BM25 знаходить точний рядок на кшталт коду помилки «TS-999», де embedding-модель знайде «щось про коди помилок», але провалює перефразування, як наше Q2. Embeddings ловлять зміст, але можуть пропустити рідкісний ідентифікатор. Тому продакшн-RAG зазвичай гібридний.

Друга системна вада — фрагмент губить контекст. Приклад Anthropic: фрагмент «The company's revenue grew by 3% over the previous quarter» не каже, яка компанія і який квартал, тож ні пошук, ні модель не прив'яжуть його до питання про ACME у Q2 2023. Contextual Retrieval (Anthropic, 19.09.2024) перед індексацією просить модель дописати до кожного фрагмента 50–100 токенів пояснення («This chunk is from an SEC filing on ACME corp's performance in Q2 2023…») і індексує вже доповнений текст, і в embeddings, і в BM25. Результати статті — частка невдалих пошуків серед top-20 (1 − recall@20), базова — 5,7%:

КонфігураціяНевдалих пошуків
Contextual Embeddings3,7% (−35%)
+ Contextual BM252,9% (−49%)
+ reranking1,9% (−67%)

Одноразова ціна контекстуалізації в статті — $1,02 за мільйон токенів документів: документ кешується, і кожен його фрагмент дописується з кешу. Там само: передавати моделі top-20 фрагментів ефективніше, ніж top-10 чи top-5. Це той самий висновок, що й наш top-3 → top-8: на невеликому k пошук губить потрібне.

Для джерел у відповіді Claude API має блоки search_result: ваші фрагменти передаються з source і title, і модель цитує їх так само, як результати вебпошуку. За документацією, їх підтримують усі активні моделі, крім Claude Haiku 3, без beta-заголовка. Chunking, гібридне ранжування, reranking і evals пошуку — тема уроку 9.2. Тут достатньо знати, що RAG — це окремий пайплайн з власними метриками, а не прапорець у запиті.

ГібридиВажелі складаються

Більшість продуктів мають обидва дефіцити одночасно, тож важелі комбінують за ролями:

  • RAG + few-shot: факти приходять з пошуку, формат і тон — з правил і прикладів. Експеримент 1 показав, що приклади і правила закривають різні вимоги, тож одне не замінює іншого.
  • RAG + prompt caching: стабільна частина (інструкції, приклади, довідник, який потрібен завжди) стоїть на початку і кешується, знайдені фрагменти йдуть після неї, перед питанням. Кеш префіксний: фрагменти, що змінюються з кожним запитом, на початку промпту вбивають кеш усього, що за ними (урок 1.5).
  • Fine-tune для формату + RAG для фактів: донавчена модель засвоює формат і політику відповіді, а факти отримує в контексті, тож оновлення знань не вимагає перенавчання. Для Claude роль донавчання тут виконує промпт; сам патерн актуальний для відкритих моделей.
  • Корпус у кеші + інструменти: довідник курсу лежить у кешованому префіксі, а живі дані (розклад, оцінки студентів) агент читає інструментом на вимогу.

Окремий випадок — coding-агенти. Claude Code свідомо не тримає векторного індексу коду і шукає grep-ом, а Cursor улітку 2026 прибрав семантичний індекс (урок 3.1). Для коду, який змінюється щохвилини, «інструмент пошуку на вимогу» переміг «індекс наперед» з тих самих причин, що й у таблиці вище: свіжість і точні збіги ідентифікаторів.

Квіз11 питань

11 питань
1. Бот підтримки має відповідати з довідника на 30 тис. токенів, який оновлюють раз на місяць. З чого почати?
Так. Корпус на порядок нижчий за поріг 200 тис., кеш робить повторні питання дешевими, а модель бачить усе, включно з відповідями на «перелічіть усі».
Під 200 тис. токенів Anthropic радить просто включити всю базу з кешем. RAG додає пайплайн і промахи, донавчання засвоює факти гірше за контекст і застаріває з кожною редакцією.
2. У експерименті 1 приклади дали 12/12 карток з «## Значення», але notes вийшли задовгими у 7 з 12. Що з цього випливає?
Так. Межу, якої приклад сам не порушує, з нього не вивести. Правила + приклади дали 12/12 і на межах, і на стилі.
Стиль з прикладів модель засвоїла повністю (12/12), отже читає їх добре. Межі довжини в прикладах не записані, тому їх задають правилами і перевіряють кодом.
3. RAG-бот відповідає «у документах цього немає», хоча відповідь у корпусі є. Яка причина найімовірніша?
Так. Як у Q2 експерименту 2: «рибалити» проти «вилов», потрібний розділ шостий у рейтингу. Модель чесно звітує про те, що отримала.
Модель відповіла правильно щодо того, що бачила. Промахнувся пошук: лексичний індекс не зв'язав різні слова, а top-3 відрізав потрібний фрагмент.
4. Команда хоче донавчити Claude Sonnet 5.5 на фірмовому тоні. Що відповісти станом на 15.10.2026?
Так. Глосарій: API fine-tuning не пропонує. У Bedrock у списку лише Claude 3 Haiku з EOL 10.09.2026. Тон — поведінка, її задає промпт.
API fine-tuning не пропонує, а в Bedrock з моделей Anthropic донавчається лише Claude 3 Haiku, і та з EOL. Для тону достатньо правил і прикладів.
5. Регламент компанії змінюється щотижня, його 2 млн токенів. Який важіль для знань?
Так. Корпус більший за вікно, свіжість важлива, а джерело з датою редакції потрібне для перевірки відповіді.
2 млн токенів не влазять у вікно 1 млн. Ваги відтворюватимуть стару редакцію до наступного навчання і не покажуть, звідки взято відповідь.
6. Корпус 150 тис. токенів, модель Haiku 5.5, тисяча питань на день. Що врахувати, кладучи весь корпус у промпт?
Так. Поріг Haiku 5.5 — на запит, і кеш теж рахується. Варіанти: стиснути корпус до 100 тис., Sonnet 5.5 без надбавки, або RAG.
Кеш працює, але читання кешу теж дорожчає вп'ятеро ($0,05 замість $0,01 за MTok). Інші моделі 4.6+ надбавки за довжину не мають, а Haiku 5.5 має.
7. Що саме робить Contextual Retrieval?
Так. Пояснення генерує модель з кешованого документа, а доповнений фрагмент іде і в embeddings, і в BM25: −49% невдалих пошуків, з reranking −67%.
Запит не змінюється, розмір фрагмента теж. До кожного фрагмента додається коротке пояснення, з якого він документа і про що.
8. Користувачі питають про вільні місця на семінарі, дані змінюються щохвилини. Що обрати?
Так. Будь-яка копія живих даних застаріла в момент запиту. Джерело істини — система бронювання, модель звертається до неї інструментом.
І нічний індекс, і п'ятихвилинний промпт — копії. Для даних, що змінюються щохвилини, потрібен виклик до джерела в момент питання.
9. «Перелічіть усі інвазійні види» — RAG top-3 назвав два з трьох. Чим ця помилка гірша за «у матеріалах цього немає»?
Так. «Згадано два інвазійні види» звучить як факт. Для агрегації потрібен увесь корпус, структурований індекс або кілька пошуків.
Різниця в ціні мізерна, і семантичний пошук з k = 3 так само обрізав би розкидані фрагменти. Небезпека в тому, що часткова відповідь не схожа на часткову.
10. RAG + кеш: куди поставити знайдені фрагменти в промпті?
Так. Кеш префіксний: стабільна частина на початку читається з кешу, змінні фрагменти після неї кешу не ламають.
Фрагменти змінюються з кожним запитом. Якщо вони стоять на початку чи в системному промпті, префікс щоразу інший і кеш нічого не дає.
11. Чому в експерименті 2 друге й наступні питання з усім корпусом у кеші вийшли дешевшими за RAG top-3 без кешу?
Так. 14,5 тис. × $0,01 за MTok ≈ $0,00014 проти 2,25 тис. × $0,10 ≈ $0,00023. Платите один раз за запис, далі — десяту частину.
Вихід у long context був навіть трохи довшим (86 проти 71 токена). Різницю дає ціна читання кешу — 0,1× від звичайного входу.

Домашнє завданняДві задачі з AI-перевіркою

1. Стек адаптації для вашої AI-фічі

Візьміть фічу свого продукту або Lectern, розкладіть її на етапи, для кожного поставте діагноз «знання чи поведінка», оцініть корпус у токенах і вимогу до свіжості, оберіть важіль за деревом рішень і порахуйте ціну тисячі запитів з кешем і без. Підсумок — ADR на 10–15 рядків.

2. Повторіть експеримент на своїх даних

Корпус на 10–30 тис. токенів, п'ять питань п'яти типів, дві умови: весь корпус у промпті проти BM25 top-k. Таблиця правильності, токенів і ціни, розбір кожної помилки і висновок, з якого k пошук перестає губити відповіді.
