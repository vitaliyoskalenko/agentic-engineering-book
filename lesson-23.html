Що не переноситься дослівно

Shell(git) у Cursor дозволяє будь-яку підкоманду git, бо збігається перше слово команди, тож щоб дозволити git status, але не git push, потрібна форма command:args. У Codex .rules, за документацією, керують командами поза пісочницею; те, що вміщається в пісочницю, у пресеті Auto виконується без питань, тож межу тут тримає пісочниця, а не правило. Профіль дозволів Codex ігнорується, щойно будь-який шар конфігу задає sandbox_mode або ви передаєте --sandbox.

Квіз11 питань

11 питань
1. У CI потрібен JSON за схемою з Codex. Як?
Так. --output-schema бере файл зі схемою, -o записує фінальну відповідь.
--json — потік подій JSONL (thread.started, turn.completed…), а не схема відповіді. --json-schema — прапорець Claude Code; у Codex це --output-schema з файлом.
2. Скрипт з Cursor CLI має реально змінювати файли. Що написати?
Так. Сторінка headless прямо каже, що без --force зміни лише пропонуються, тож прапорець ставлять явно.
Довідник прапорців і сторінка headless тут суперечать одне одному. Коли документація розходиться, обирають варіант, який працює за обох прочитань: --force. У --mode є лише plan і ask.
3. Як обмежити codex exec десятьма ходами?
Так. Ліміт ходів і бюджету є лише в Claude Code (--max-turns, --max-budget-usd); у Codex ходи рахують за подіями в --json.
У довіднику прапорців codex exec і в довіднику config.toml ліміту ходів немає, як і ключа max_turns: -c задає лише наявні ключі.
4. У Codex CLI агент зіпсував три файли. Як відкотити?
Так. Undo в Codex немає, документація радить git-чекпоінти до і після задачі.
Esc Esc у Codex редагує попереднє повідомлення й розгалужує чат, але файлів не чіпає. /rewind є в Claude Code і Cursor CLI, а в Codex його немає.
5. У CI-скрипті написано codex -p review "перевір diff". Що буде?
Так. Без підкоманди codex запускає TUI, а -p review накладає ~/.codex/review.config.toml. Headless — codex exec або codex review.
У Claude Code і Cursor -p означає print, а в Codex прапорець є, але це --profile. Це запуск інтерактивного інтерфейсу, а не headless.
6. Розробник у Cursor обрав Auto й вирішив, що команди тепер схвалює класифікатор. Так?
Так. Схвалення задають Run Modes. І ще одна пастка: /auto-run — аліас Run Everything, тобто режиму взагалі без перевірок.
Auto в Cursor — маршрутизатор моделей (Cursor Router), а не режим схвалень; Run Everything вмикає /auto-run, а не Auto. Режими виконання — окреме налаштування: Settings → Agents → Approvals & Execution.
7. Після оновлення Codex codex --profile ci перестав брати налаштування з таблиці [profiles.ci]. Чому?
Так. [profiles.x] і селектор profile = "x" більше не читаються; файл профілю з ключами верхнього рівня лежить між користувацьким і проєктним шаром.
Профілі є, і проєктний файл тут ні до чого: змінився формат — один TOML-файл на профіль у $CODEX_HOME.
8. Команда живе на AGENTS.md. Розробник додав CLAUDE.local.md, і його Claude Code «забув» команду тестів. Що найнадійніше?
Так. Варіанти A і D з реальної перевірки: імпорт не залежить від локальних файлів і не дублює AGENTS.md. Для однієї людини — ще claude-md-and-agents-md у /config.
Копія правил розійдеться з оригіналом, а перейменування відбере файл у Codex і Cursor.
9. У .cursor/cli.json треба дозволити git status і git diff, але не git push. Що не так з "allow": ["Shell(git)"]?
Так, і push теж. Вужче — форма command:args або git узагалі поза allow: у режимі Allowlist він питатиме.
У документації Shell(git) — «Allow any git subcommand». Окремого ask у Cursor немає: питає те, чого немає в allow, а push тут якраз в allow.
10. Як у Codex заборонити агентові читати .env?
Так. Профіль дозволів — бета, і його перекриває будь-який sandbox_mode чи --sandbox, тож перевірте, що його ніде не задано.
Рядок в AGENTS.md — прохання, а не межа. prefix_rule керує командами поза пісочницею й за префіксом: head .env чи grep він не впізнає.
11. Проєкт на Codex і Cursor. Куди покласти спільні skills, щоб обидва їх бачили без копій?
Так. .agents/skills — проєктна тека skills і в Codex, і в Cursor.
.claude/skills Cursor читає, а Codex — ні, і /import зробив би якраз копію. Codex шукає .agents/skills від cwd до кореня репо, тож симлінк у .cursor/skills — зайва ланка.
