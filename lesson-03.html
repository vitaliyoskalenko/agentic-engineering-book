06

Перша сесіяВхід, довіра до папки, дозволи

  1. Запуск у корені проєкту, не в домашній теці: cd lectern && claude --permission-mode manual.
  2. Вхід. Браузер не відкрився — c копіює посилання; у WSL, SSH чи контейнері сторінка дасть код для Paste code here if prompted.
  3. Діалог довіри (workspace trust dialog) перелічує, що дозволять налаштування папки: правила дозволів, додаткові каталоги, hooks. У git-репозиторії довіра — на корінь, у домашній теці — до кінця сесії.
Діалог довіри — лише в інтерактивній сесії

У claude -p його немає: hooks непереглянутого чужого репозиторію виконаються, а MCP-сервери з .mcp.json підключаться без питань.

“The workspace trust dialog is skipped when Claude is run in non-interactive mode … Only use this in directories you trust.” — claude --help, 2.1.299

Запити дозволів і режими

Питати (permission prompt) чи діяти самому перед редагуванням, командою або мережею — вирішує режим дозволів:

РежимЩо виконується без питаньКоли
manual (у конфігурації — default)Лише читанняНезнайомий код, перші сесії
acceptEditsЩе й редагування і файлові команди (mkdir, mv, cp…)Ітерації з переглядом diff
planЧитання; редагування заблоковані до схвалення плануДослідити до змін
autoУсе, але модель-класифікатор перевіряє дії у фоніДовгі задачі

З 2.1.283 інтерактивні сесії в терміналі та VS Code стартують в auto; на початку курсу працюйте в Manual (Shift+Tab або --permission-mode). dontAsk — для CI зі строгим списком інструментів, bypassPermissions — лише в ізольованому контейнері чи VM (модуль 4).

zsh — ~/lectern
$ claude --permission-mode manual
прапорець перевірено в claude --help (2.1.299): choices "acceptEdits", "auto", "bypassPermissions", "manual", "dontAsk", "plan"

Правила «дозволити / питати / заборонити» для окремих інструментів — /permissions.

Пісочниця ОС: типовий workspace-write пише лише в робочу папку, без мережі; коли питати вас, вирішує окрема політика схвалення. До довіри до папки (онбординг або /permissions) може стартувати лише для читання.

Agent (типовий, усі інструменти), Plan (план з уточнювальними питаннями), Ask (лише читання); Shift+Tab, /plan, /ask. Правила Shell(…), Read(…), Write(…) — у ~/.cursor/cli-config.json або .cursor/cli.json.

/init: інструкції для агента

ІнструментФайлЩо робить /init
Claude CodeCLAUDE.md у корені проєктуЗаписує команди збірки, тестів і конвенції з коду; наявний файл не перезаписує, а пропонує покращення.
Codex CLIAGENTS.mdСтворює заготовку в поточній папці — дописуєте ви.
Cursor CLI.cursor/rulesКоманди немає; читає ще AGENTS.md і CLAUDE.md у корені.

Claude Code з 2.1.277 читає AGENTS.md, лише коли немає CLAUDE.md. Тому спільні правила — в AGENTS.md, а CLAUDE.md підключає їх рядком @AGENTS.md і додає специфіку Claude.

Архітектура

/init бачить лише код. Чому такий стек, чого не чіпати, що означає «готово» — дописує людина (домашнє завдання 2; детально — модулі 4 і 5).

Чому src layout

Python ставить поточну папку на початок шляху імпорту: з пакетом у корені тести імпортують «сирий» код, і зламана збірка пройде непоміченою. src layout змушує тести брати встановлений пакет — тому він типовий в uv init.

Квіз10 питань

10 питань
1. Студент має безкоштовний план claude.ai. Чи зможе він працювати в Claude Code?
Так. Документація прямо каже: безкоштовний план claude.ai доступу до Claude Code не дає.
Спосіб встановлення на доступ не впливає, а урізаного безкоштовного режиму Claude Code не має. Потрібна платна підписка, Console (API) або Bedrock, Google Cloud чи Foundry.
2. У вас є підписка Max, але в ~/.zshrc лишився export ANTHROPIC_API_KEY=…. Що станеться в нічному скрипті з claude -p?
Саме так. Питання про ключ буває лише в інтерактивному режимі. Перевіряйте /status і прибирайте змінну, якщо вона не потрібна.
Питання про ключ і згода на нього бувають лише в інтерактивному режимі. У -p діалогів немає, а ANTHROPIC_API_KEY використовується завжди, коли він заданий, тож витрати підуть з API-рахунку.
3. Ви встановили Claude Code через brew install --cask claude-code. Як він оновлюватиметься?
Так. Автоматично оновлюється нативне встановлення. Cask claude-code — це stable, claude-code@latest — latest.
Автоматично оновлюється лише нативне встановлення, Homebrew — вручну. Канал визначає назва cask: claude-code — stable, claude-code@latest — latest.
4. На Node 20 ви виконали npm install -g @anthropic-ai/claude-code. Що буде?
Так. Пакет вимагає Node 22+, але завантажує нативний бінарний файл, який Node під час роботи не використовує.
Документація описує саме цей випадок: лише попередження EBADENGINE, встановлення завершується, а npm завантажує нативний бінарний файл, якому Node під час роботи не потрібен. Вимога Node 22+ все одно діє, тож краще оновити Node.
5. claude doctor на робочому ноутбуці показує Auto-update channel: latest, а вам потрібно менше несподіваних регресій. Що зробити?
Так. Stable отримує версію приблизно тижневої давнини, без релізів із серйозними регресіями, і далі оновлюється сам.
Канал — це налаштування, а не помилка, тож /doctor його не «виправляє», а claude update ставить найновішу версію негайно. Stable дає версію приблизно тижневої давнини без серйозних регресій і далі оновлюється сам.
6. Чому діалог довіри не допомагає, коли ви запускаєте claude -p у щойно склонованому репозиторії?
Так. claude --help радить використовувати -p лише в папках, яким ви довіряєте.
У -p діалогу довіри немає взагалі: hooks із налаштувань репозиторію виконаються, а MCP-сервери з .mcp.json підключаться без питань. Тож чужий репозиторій спершу переглядають.
7. У репозиторії є лише AGENTS.md, без CLAUDE.md. Що прочитає Claude Code 2.1.299?
Так. Якщо з'явиться ще й CLAUDE.md, за замовчуванням читатиметься лише він. Тому спільні правила підключають рядком @AGENTS.md.
З версії 2.1.277 Claude Code сам читає AGENTS.md, коли поруч немає CLAUDE.md. Рядок @AGENTS.md потрібен в іншому випадку: коли є обидва файли і CLAUDE.md має підключити спільні правила.
8. Агент змінив файл через shell-команду, а не через Edit. Як надійно відкотити цю зміну?
Так. Чекпоінти Claude Code не відстежують зміни, зроблені Bash-командами, і не замінюють систему контролю версій.
Документація попереджає: чекпоінти не відстежують змін від Bash-команд, а відкат «з пам'яті агента» нічим не перевірений. git бачить будь-яку зміну у файлах, хоч би як її зроблено.
9. Навіщо Lectern має src layout (src/lectern/), а не пакет у корені?
Так. Python додає поточну папку на початок шляху імпорту, і src layout прибирає цю пастку.
pytest працює з обома структурами, а .venv від коміту береже .gitignore. Python додає поточну папку на початок шляху імпорту, і src layout змушує тести перевіряти встановлений пакет.
10. У демо агент додав у README uv run pytest, хоча не зміг запустити цю команду. Яка правильна реакція?
Так. Рішення ухвалює людина на основі diff. Неперевірену інструкцію краще не комітити.
Звіт агента — не доказ, а неперевірену інструкцію краще не комітити. bypassPermissions — лише для ізольованого контейнера чи VM, не для хост-машини. Правильний шлях: переглянути diff і вирішити свідомо.

Домашнє завданняДві задачі з AI-перевіркою

1. Звіт «середовище готове»

Виводи команд чек-листа «Практика» (email і організацію приховати) плюс одна проблема налаштування і її розв'язок — або та, яку найімовірніше зустріне колега на іншій ОС.

2. CLAUDE.md для Lectern: вручну проти /init

Напишіть CLAUDE.md для скелета Lectern вручну, потім виконайте /init в іншій гілці і порівняйте: що агент знайшов сам, чого не міг знати, що лишиться у фінальній версії.
