01

Від прохання до гарантіїЩо змінює хук

Рядок у CLAUDE.md — прохання до моделі. Hook — команда, яку harness запускає сам у визначеній точці циклу агента. Вона отримує JSON про подію і своїм кодом виходу чи JSON-відповіддю може заблокувати дію, додати моделі контекст або не дати завершити хід. Модель його не викликає і пропустити не може.

Три спостереження з прогонів цього уроку на Lectern (Claude Code 2.1.300, Haiku 5.5):

  1. Прохання часто працює. З правилом «Never read lectures/private/» у CLAUDE.md модель в обох прогонах сама відмовилась писати в цю теку. Без CLAUDE.md вона одразу запустила mkdir -p lectures/private && cp …, і зупинив її лише хук.
  2. Самоперевірка агента бреше. Агент перевірив п'ять цитат через lectern check --quote, усі ok, і відзвітував «готово». Stop-хук прогнав повну перевірку квізу і знайшов дві цитати коротші за 5 слів (відомий баг B2) і ключ, який вгадується без лекції.
  3. Гарантія коштує мілісекунди. Stop-гейт додавав понад секунду до ходу з квізом, з них 0,7 с — імпорт SDK у lectern check. Після правки — 0,11 с.
Продуктове мислення

Хук — політика без участі моделі. Його ціна — затримка на кожній події і підтримка скрипта. Окупається він там, де одна пропущена помилка дорожча за тисячі прогонів: персональні дані, зламаний квіз, секрет у промпті.

02

Модель хуківПодія → matcher → обробник

Конфігурація має три рівні вкладеності: подія (точка життєвого циклу), matcher (фільтр, наприклад назва інструмента) і один чи кілька обробників (handler).

{ "hooks": {
  "PostToolUse": [  // подія
    { "matcher": "Edit|Write", // фільтр
      "hooks": [  // обробники
        { "type": "command",
          "command": "${CLAUDE_PROJECT_DIR}/scripts/hooks/after_edit.sh",
          "args": [],
          "timeout": 30 } ] } ] } }

Коментарі — лише для пояснення: у settings.json їх не можна.

Matcher

Matcher фільтрує різні поля для різних подій. Для інструментальних подій це tool_name, для SessionStart — source (startup, resume, clear, compact, fork), для PreCompact — manual|auto. UserPromptSubmit, Stop і PostToolBatch matcher не підтримують: доданий він мовчки ігнорується. Тип matcher-а визначають символи в ньому:

  • Лише літери, цифри, _ - , | і пробіли — точний збіг або список: Edit|Write.
  • Будь-який інший символ — неякірний JavaScript-регекс. Edit.* зловить і NotebookEdit, тому для точного збігу пишуть ^Edit$. MCP-інструменти мають вигляд mcp__сервер__інструмент. mcp__memory без .* — точний рядок, і він не збігається з жодним інструментом.
  • Поле if звужує фільтр синтаксисом правил дозволів ("Bash(git *)"), але best-effort: нерозібрану команду хук отримує завжди.

Пастка exit 1

Звичний exit 1 нічого не блокує: політика з exit 1, хибним шляхом до скрипта (127) чи падінням інтерпретатора пропускає все. А exit 1 з валідним JSON — успіх, рішення бере JSON. Для політик — exit 2 і з v2.1.295 "onFailure": "block": збій чи таймаут блокує як exit 2 (крім Stop-подій, де модель не полагодить хук, що не запускається).

Вихід: JSON

stdout читається як JSON, лише якщо там один об'єкт без зайвого тексту: рядок з вашого .bashrc тихо перетворює рішення на текст.

ПолеДеЩо робить
continue: false + stopReasonбудь-яка подіязупиняє Claude повністю; має пріоритет над рештою рішень

additionalContext пишіть фактами, а не наказами: текст, схожий на позасистемну команду, модель може прийняти за prompt injection і показати вам замість того, щоб врахувати.

Паралельність, таймаути, async

  • Усі хуки, що збіглися, запускаються паралельно і доходять до кінця: deny одного не скасує побічних ефектів іншого, а з кількох updatedInput перемагає той, що завершився останнім.
  • Таймаут скасовує хук і відкидає його вихід: на PreToolUse виклик проходить, якщо немає onFailure: "block".
  • "async": true — фоновий хук без права блокувати; результат прийде наступним ходом. asyncRewake будить Claude на exit 2. У -p незавершені async-хуки вбиваються при виході.

Пастка форматера · виміряно

У Lectern 10 з 11 Python-файлів не відформатовані. Наївний ruff format "$f" перетворює правку на 4 рядки в diff +96 / −31, і зміну агента на рев'ю вже не видно. Тому храповик (ratchet): файл, неформатований у HEAD, хук лише лінтить. Решту форматують окремим комітом.

За документацією exit 2 хука зупиняє виклик ще до перевірки правил, тобто блок сильніший за allow. Але з deny-правилом на шлях хук на Write не запустився зовсім, і модель отримала загальне «denied». Для файлових інструментів досить правила, а шлях усередині shell-команди правилом не опишеш — тут потрібен хук:

# guard_paths.py · PreToolUse, matcher "Bash"
inp = json.load(sys.stdin)
command = inp.get("tool_input", {}).get("command", "")
flat = re.sub(r"/+", "/", command.replace("/./", "/"))
hit = next((p for p in PROTECTED if p in flat), None)
if hit:
    print(f"{hit}/ is off-limits to agents: …",
          file=sys.stderr)
    sys.exit(2)

# stop_gate.py (кінець, скорочено)
if not problems:              # квіз чистий
    state.unlink(); sys.exit(0)
report = "lectern check on the quiz you wrote:\n- "
report += "\n- ".join(problems)
if inp.get("stop_hook_active"):  # одне коло вже було
    state.unlink()
    print(json.dumps({"systemMessage": report}))
else:
    print(json.dumps({"decision": "block",

Правило

Порада — у CLAUDE.md. Те, що мусить триматися в сесії, — у правила дозволів, якщо їхній синтаксис дотягується; якщо ні — у хук. Те, що мусить триматися для всіх і завжди, — у CI. Хук і CI запускають один і той самий скрипт: гейт Lectern викликає lectern check --json, а не власну копію правил.

Безпека хуків

Command-хук виконується з усіма правами вашого користувача. Інтерактивна сесія чекає діалогу довіри до теки, а -p і SDK вважають теку довіреною, тож хуки чужого репозиторію виконуються одразу (урок 3.4). Захист — --bare або --settings '{"disableAllHooks": true}'. disableAllHooks береться після злиття рівнів (false у проєкті перекриває ваш true) і не вимикає managed-хуки. Організація ставить allowManagedHooksOnly: true: працюють лише managed-хуки і примусово ввімкнені плагіни. Агент не має правити свої хуки — у Lectern це ask. І межа: плагін-мод (JavaScript-хуки в процесі Claude Code) з tool.check може схвалити виклик, заблокований вашим PreToolUse-хуком, якщо той не з managed settings.

ПрактикаЩо зробить хук?

11

Квіз11 ситуацій

11 питань
1. Хук-політика на PreToolUse написана на Python. Хтось перейменував скрипт, і шлях у settings.json тепер хибний. Що буде з викликами Bash?
Так. Будь-який код, крім 0 і 2, — неблокувальна помилка, і дія відбувається. Для політики потрібен "onFailure": "block" і перевірка першого запуску.
Скрипт, що не стартує, дає код 127, тобто неблокувальну помилку: дія відбувається, у транскрипті лише «hook error». Захист — "onFailure": "block" з v2.1.295.
2. Агент має на старті кожної сесії, і після --resume теж, бачити поточну гілку й відкриті задачі з трекера. Що обрати?
Так. SessionStart повторюється з source: "resume" і дає свіжі дані. Контекст з UserPromptSubmit при resume відтворюється з транскрипту, тобто застарілий.
CLAUDE.md — прохання, і модель може його пропустити. UserPromptSubmit коштує часу на кожному промпті, а при resume його контекст береться з транскрипту, не перераховується. SessionStart робить саме це: дані на старті і при resume.
3. Stop-хук вимагає «усі тести зелені», але Bash у сесії вимкнено, а stop_hook_active хук не перевіряє. Чим закінчиться хід?
Так. У прогоні цього уроку: 9 блоків, потім «overriding and ending turn», 10 ходів. Стелю змінює CLAUDE_CODE_STOP_HOOK_BLOCK_CAP.
У Claude Code вбудована стеля: 8 продовжень поспіль, далі блок ігнорується. Таймаут тут ні до чого, бо хук відповідає миттєво. Правильний хук перевіряє stop_hook_active і віддає рішення людині.
4. У settings є deny Edit(./data/learners/**) і PreToolUse-хук на Write, що пояснює, чому туди не можна. Що побачить агент, який пробує Write у цю теку (Claude Code 2.1.300)?
Так. Для файлового інструмента з deny на шлях хук у прогоні не викликався: рядка PreToolUse:Write у debug-лозі немає. Тому хук у Lectern стоїть лише на Bash.
Порядок «хук раніше за правила» з документації стосується блоку, сильнішого за allow. На практиці deny-правило на шлях відповіло першим, і хук навіть не запустився.
5. PreToolUse-хук перевірки команд інколи висить 10 секунд при timeout: 5, інших полів немає. Що робить Claude Code?
Так, це fail-open. У прогоні: «timed out after 1000ms», і заборонений ls виконався. З onFailure: "block" той самий хук зупинив виклик.
Таймаут скасовує хук і відкидає його рішення, а виклик іде далі. Fail-closed треба ввімкнути явно: "onFailure": "block".
6. У репозиторій, де більшість файлів не відформатовані, додали PostToolUse-хук ruff format "$f". Що з'явиться на рев'ю?
Так. У Lectern правка на 4 рядки дала diff +96 / −31. Звідси храповик: старі неформатовані файли хук лише лінтить.
ruff format переписує весь файл і повертає 0. Правка на 4 рядки стала diff +96 / −31. Спершу форматують репозиторій окремим комітом або ставлять храповик.
7. Агент записав конфіг з паролем, і PostToolUse-хук повертає {"decision": "block", "reason": "…"}. Що станеться?
Так. PostToolUse спрацьовує, коли інструмент уже виконано. decision: "block" додає reason до результату, а сесію зупиняє лише continue: false.
PostToolUse не може скасувати дію: файл уже записано. Block тут — це фідбек моделі. Зупинка всієї сесії — окреме поле continue: false.
8. UserPromptSubmit-хук відхилив промпт з ключем API, вказавши suppressOriginalPrompt: true. Що з ключем?
Так. У прогоні: 0 ходів і $0, але ключ лежав у транскрипті як queue-operation. Документація каже прямо: блокувальний хук не прибирає секрет з диска.
UserPromptSubmit уміє відхилити промпт, і модель ключа не отримала. Проте suppressOriginalPrompt прибирає текст лише з повідомлення про блок, а транскрипт сесії вже містить промпт.
9. Потрібен хук на всі інструменти MCP-сервера memory. У конфігурації стоїть "matcher": "mcp__memory". Що не так?
Так. Matcher лише з літер, цифр і _ - , | порівнюється точно. Будь-який інший символ вмикає неякірний регекс.
MCP-інструменти — звичайні інструменти в PreToolUse і PostToolUse з назвою mcp__сервер__інструмент. Але mcp__memory — точний рядок, тому потрібно .*.
10. Команда працює в Claude Code і Codex, і набір перевірок має бути однаковим. Як його організувати?
Так. Формати й семантика хуків різні, а скрипт один. CI ловить тих, у кого хуків немає взагалі.
AGENTS.md — прохання, а не перевірка. Хуки Claude Code вміє вантажити Cursor; Codex читає свої hooks.json або [hooks] і вимагає довірити кожен хук.
11. Stop-гейт викликає lectern check, і кожен хід із квізом довшає на секунду. Що робити першим?
Так. -X importtime показав 0,7 с на імпорт SDK, непотрібного для check. Після правки гейт займає 0,11 с.
Async-хук нічого не блокує, тож гейт перестане бути гейтом. Prompt-хук — це запит до моделі: повільніше і без детермінованої перевірки цитат. Вартість сиділа в інструменті, а не в хуку.

ТермінКоротко
hook eventТочка життєвого циклу, в якій harness запускає хуки; у Claude Code 2.1.300 їх 33.

PostToolUseПодія після успішного виклику; скасувати не може, лише дає фідбек моделі чи підміняє результат.

exit code 2 (block)Код виходу, що блокує дію на подіях, які це вміють; stderr стає причиною блоку.

additionalContextТекст від хука, який модель отримує як system reminder; до 10 000 символів.
prompt-based hookОбробник type: "prompt": один запит до моделі з відповіддю {ok, reason}.
disableAllHooksНалаштування, що вимикає всі хуки, крім managed; --settings вимикає їх на один запуск.
hooks menu (/hooks)Браузер хуків у Claude Code лише для перегляду: джерело і повний текст команди.

1. Хуки для власного репозиторію

Розкладіть п'ять правил свого проєкту за таблицею рішень, реалізуйте два хуки (один блокувальний, один Stop-гейт або PostToolUse), протестуйте їх через stdin, виміряйте мілісекунди в --debug-file і відтворіть один режим відмови.
