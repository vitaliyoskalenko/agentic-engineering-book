Після уроку ви зможете

  • зібрати агента з трьох інструментів і правила успіху, за яким «готово» вирішує код, а не модель;
  • написати агентний цикл на Messages API і протестувати його без мережі фейковим клієнтом;
  • перенести того самого агента на Claude Agent SDK і назвати, що саме SDK бере на себе;
  • читати ResultMessage: subtype, num_turns, total_cost_usd — і знати, чого з них не можна робити висновків;
  • запустити ту саму ідею через claude -p, codex exec чи agent -p і поставити після кожного кодову перевірку.
01

Що будуємоТри інструменти, одне правило успіху

Після модуля 2 Lectern — це команда lectern generate lecture.txt --out quiz.json. Агент читає лекцію, пише квіз на 5 питань, звіряє кожну цитату з текстом і зберігає лише те, що пройшло перевірку. Одного виклику моделі тут замало. Перевірка цитати — це дія у світі, і те, що агент робитиме далі, залежить від її результату. Саме за цією ознакою в уроці 2.4 workflow відрізнявся від агента.

Квіз вважається готовим, коли save_quiz його прийняв, і більше ніяк. Модель не може сама оголосити успіх: end_turn без збереженого квізу в шляху A означає ще один хід, а не результат. Це критерій «виконано» зі StopPolicy уроку 2.2, тільки тепер він живе в коді інструмента.

02

ІнструментиЧистий Python без LLM

tools.py не імпортує ні anthropic, ні Agent SDK. Обидва шляхи загортають той самий диспетчер Session.call(name, args), який повертає пару «текст для моделі, is_error». Схеми входу теж лежать в одному місці. Шлях A віддає їх як tools зі strict: true, шлях B — як @tool.

# src/lectern/tools.py (уривок; повний файл — у console/lectern/)
SCHEMAS = {  # name -> (description, JSON Schema входу); одне джерело для A і B
    "check_quote": (
        ("Check that a quote occurs verbatim in the lecture (line breaks, quote marks and "
         "dashes are normalized). Returns ok, or the closest sentence of the lecture."),
        {"type": "object", "properties": {"lecture_id": _STR, "quote": _STR},
         "required": ["lecture_id", "quote"], "additionalProperties": False}),
    # read_lecture, save_quiz — так само
}

def check_quote(self, lecture_id: str, quote: str) -> dict:
    text = self.read_lecture(lecture_id)
    if quote in text:
        return {"ok": True, "match": "exact"}
    if norm(quote) in norm(text):            # NFKC, лапки, тире, переноси (урок 1.4)
        return {"ok": True, "match": "normalized"}
    # підказка — з оригіналу, не з norm(): модель копіює її в квіз дослівно
    sentences = re.split(r"(?<=[.!?])\s+", re.sub(r"\s+", " ", text))
    def score(s: str) -> float:
        return difflib.SequenceMatcher(None, norm(quote), norm(s)).ratio()
    return {"ok": False, "match": "missing", "closest_sentence": max(sentences, key=score)}
  1. Негативний вердикт — не помилка інструмента. «Цитати немає» — це успішний виклик із відповіддю «ні». is_error лишається для справжніх збоїв: невідомий id, аргументи не за схемою, квіз, який не можна зберегти. Якщо їх змішати, ламається і журнал, і логіка зупинки (див. «Типові помилки»).
  2. Підказка має бути придатною для копіювання. Модель вставляє closest_sentence у квіз символ у символ. Тому підказку беремо з оригінального тексту, з типографськими лапками й тире, а не з нормалізованого.
  3. save_quiz перевіряє все сам. Він не довіряє тому, що агент нібито викликав check_quote. Правила validate(): рівно n пунктів; 4 різні варіанти; answer — індекс варіанта; цитата має щонайменше 5 слів і є в лекції; у тексті немає символу U+FFFD. Ці самі правила запускає lectern check для агентів, які працюють без нашого циклу.
  4. Схема пункту квізу — мінімальна: question, options, answer, quote. Розширена схема з уроку 2.1 (correct_index, source_quote, skill) знадобиться для evals у модулі 12; для v0 агента кожне додаткове поле — ще одне місце, де модель може помилитися.
  5. Регістр не нормалізуємо. Цитата «Тому в Python…» до тексту «Саме тому в Python…» не пройде: дослівність важливіша за зручність моделі.
03

Шлях AЦикл на Messages API

Протокол tool_use → tool_result розібрано в уроці 2.1, причини зупинки — у 2.2. Тут вони складаються в один файл. Нові тут хіба що рішення, позначені коментарями.

  • client — параметр. Завдяки одному рядку client or anthropic.Anthropic() цикл можна тестувати без мережі, а в продакшні підставляти клієнт із власними таймаутами й ретраями.
  • Цикл не зупиняється «з ввічливості». Агент закінчує роботу в двох випадках: квіз пройшов save_quiz (повертаємо Run, не просячи моделі фінального тексту) або закінчився ліміт. Будь-який інший stop_reason одразу дає помилку. max_tokens посеред виклику означає обрізаний JSON, а refusal не можна «дотиснути» підказкою.
  • max_turns тут — це запити до моделі, бо лічильник наш. У шляху B він рахує інше (розділ «Справжній прогін»).
  • Немає tool_choice. Примусовий виклик (any/tool) на Opus 5.5 і Sonnet 5.5 повертає 400. Документація радить замість нього auto, підказку в промпті й strict: true, і код працює однаково на всіх трьох моделях.

Тести без мережі: фейковий клієнт

Циклу потрібні від відповіді лише stop_reason, usage і блоки з атрибутами type, id, name, input. SimpleNamespace дає саме це. Фейк віддає записані відповіді по черзі й зберігає знімок кожного запиту, тож можна перевірити, що саме побачила б модель.

# tests/test_agent_api.py (уривок)
class FakeClient:
    def __init__(self, *replies):
        self.replies, self.requests = list(replies), []
        self.messages = self  # client.messages.create(...)

    def create(self, **kwargs):
        self.requests.append(dict(kwargs, messages=list(kwargs["messages"])))  # знімок історії
        return self.replies.pop(0)

def test_rejected_quote_goes_back_and_the_agent_fixes_it(s):
    client = FakeClient(
        reply("tool_use", use("t1", "read_lecture", lecture_id="l4")),
        reply("tool_use", use("t2", "save_quiz", items=quiz("Колізія виникає, коли ключі збігаються."))),
        reply("tool_use", use("t3", "save_quiz", items=quiz(LECTURE))),
    )
    r = run(s, "l4", client=client)
    assert (r.turns, r.input_tokens) == (3, 300)
    rejected = client.requests[2]["messages"][-1]["content"][0]
    assert rejected["tool_use_id"] == "t2" and rejected["is_error"] is True

Ще три тести закріплюють правила зупинки: end_turn без квізу тричі поспіль дає AgentError і не рахується успіхом; max_tokens і refusal одразу завершують роботу помилкою; у запиті немає temperature, і всі схеми мають strict. Поведінку моделі такі тести не перевіряють. Вони гарантують, що ваш цикл правильно реагує на будь-яку поведінку моделі. Якість самих квізів міряють evals (модуль 12).

Шлях BТой самий агент на Claude Agent SDK

Claude Agent SDK — це Claude Code, оформлений як бібліотека. query() запускає підпроцес із вбудованим бінарником Claude Code, і цикл, виклики інструментів, історію та кеш веде вже він. Ваші функції підключаються як in-process MCP-сервер: він живе у вашому процесі й не має окремої служби чи порту. Автентифікація така сама, як у CLI, тому без API-ключа SDK працює від залогіненого claude.

# src/lectern/agent_sdk.py (без імпортів)
SERVER = "lectern"
ALLOWED = [f"mcp__{SERVER}__{name}" for name in SCHEMAS]
READ_ONLY = {"read_lecture", "check_quote"}  # без побічних ефектів: можна викликати паралельно

def build_server(session: Session):
    """Ті самі три функції, загорнуті в in-process MCP-сервер."""
    def wrap(name: str):
        desc, schema = SCHEMAS[name]

        @tool(name, desc, schema, annotations=ToolAnnotations(readOnlyHint=name in READ_ONLY))
        async def handler(args: dict) -> dict:
            text, is_error = session.call(name, args)
            return {"content": [{"type": "text", "text": text}], "is_error": is_error}
        return handler
    return create_sdk_mcp_server(SERVER, tools=[wrap(name) for name in SCHEMAS])

async def run(session, lecture_id, *, model="haiku", max_turns=12, max_budget_usd=0.50,
              on_message=lambda m: None) -> ResultMessage:
    options = ClaudeAgentOptions(
        model=model,
        system_prompt=SYSTEM,                    # рядок замінює промпт Claude Code повністю
        mcp_servers={SERVER: build_server(session)},
        tools=[],                                # жодних вбудованих Read/Bash/Edit
        allowed_tools=ALLOWED,                   # наші три інструменти — без запиту дозволу
        strict_mcp_config=True, setting_sources=[],  # не тягнути MCP і налаштування машини
        max_turns=max_turns, max_budget_usd=max_budget_usd,
    )
    result = None
    try:
        async for message in query(prompt=TASK.format(lecture_id=lecture_id, n=session.n),
                                   options=options):
            on_message(message)
            if isinstance(message, ResultMessage):
                result = message
    except Exception as e:  # query() кидає виняток після error_max_turns / error_max_budget_usd
        raise AgentError(f"{type(e).__name__}: {e}") from e
    if session.saved is None or result is None:
        raise AgentError(f"no valid quiz ({result.subtype if result else 'no result'})")
    return result
Поле ClaudeAgentOptionsЩо дає Lectern
tools=[]Прибирає всі вбудовані інструменти з контексту. Агент бачить лише MCP-інструменти, тобто наші три.
allowed_toolsДозвіл, а не доступність: перелічені інструменти виконуються без запиту. Список не обмежує, які інструменти існують, — це робить tools.
strict_mcp_config, setting_sources=[]Ізолюють агента від машини, на якій він працює: без MCP-серверів користувача, CLAUDE.md, хуків і локальних дозволів. Без цих полів SDK завантажує все те саме, що й CLI.
system_prompt (рядок)Повністю замінює системний промпт Claude Code (урок 2.3). Інструкції з безпеки й роботи з інструментами тепер лише ваші.
max_turns, max_budget_usd12 ходів і $0,50 — стартові межі з уроку 2.2. Бюджет перевіряється після відповіді, тож межу можна перевищити на вартість одного запиту.
readOnlyHint (анотація @tool)Свої інструменти SDK типово виконує послідовно. Позначені як read-only можуть виконуватися паралельно.

query() на кожен виклик відкриває нову сесію, і для «одна лекція — один запуск» більшого не треба. ClaudeSDKClient тримає сесію між викликами, вміє interrupt() і потрібен, коли наступна дія залежить від відповіді, наприклад автор лекції править квіз у діалозі. До нього повернемося в уроці 6.5.

Правило вибору

A — коли цикл є частиною продукту: потрібні контроль кожного запиту, власний кеш, аудит, нестандартна зупинка, а важкого підпроцесу бути не повинно. B — коли потрібні готові можливості harness: вбудовані інструменти, дозволи, хуки, compaction, сесії, а підпроцес з CLI допустимий. Інструменти в обох випадках однакові, тож перехід між A і B — це заміна одного файлу.

ПрактикаПеревірте терміни

11

Квіз11 питань

11 питань
1. Шлях A: модель повернула stop_reason: "end_turn" і текст «Квіз готовий!», але save_quiz не викликала. Що має зробити цикл?
Так. Успіх визначає код: квіз пройшов save_quiz. Заява моделі — ще не результат, а ліміт ходів не дасть циклу крутитися вічно.
«Готово» без збереженого квізу нічого не варте, але й не фатальне: щойно ви допишете NUDGE, розмова триває, і модель часто виправляється після одного нагадування. Тому ще один хід, доки не закінчився ліміт.
2. check_quote не знайшов цитату в лекції. Як повернути це моделі?
Так. Інструмент спрацював, просто відповідь «ні». Підказка з оригіналу дає моделі текст, який можна скопіювати символ у символ.
is_error — для збоїв інструмента: невідомий id, аргументи не за схемою. Якщо змішати вердикт зі збоєм, журнал і правила зупинки рахуватимуть не те (прогін 2). А підказка з norm(text) принесла в квіз «кортеж - може» з дефісом (прогін 3).
3. Агент на SDK пише квіз із 5 питань, max_turns=12, і в ResultMessage ви бачите num_turns: 10. Що з цього випливає?
Так. У прогоні з num_turns: 10 було 5 запитів. А з --max-turns 3 агент зупинився після 3 запитів, хоча num_turns показав 4.
num_turns не дорівнює ні запитам, ні викликам. Модель уже в прогоні 1 надсилала 5 check_quote в одній відповіді, а readOnlyHint впливає на виконання викликів, а не на кількість запитів.
4. Агента на SDK запускають на машині розробника, де в налаштуваннях є власні MCP-сервери, хуки й CLAUDE.md. Що додати в ClaudeAgentOptions, щоб агент поводився так само, як у CI?
Так. Без цих полів SDK завантажує все те саме, що й CLI. strict_mcp_config лишає тільки MCP з mcp_servers, а setting_sources=[] вимикає налаштування з файлової системи.
tools=[] прибирає лише вбудовані інструменти: MCP-сервери користувача лишаються. allowed_tools — це дозволи, а не перелік того, що існує.
5. У SDK задано allowed_tools=["mcp__lectern__save_quiz"], а tools не задано. Агент вирішує викликати Bash. Що буде?
Так. allowed_tools лише знімає запит дозволу для перелічених інструментів. Решта лишається доступною, і її виклики проходять звичайну перевірку дозволів: хід витрачено, а результат — відмова.
Доступність задають tools і disallowed_tools, дозвіл — allowed_tools, і жоден із них не є помилкою конфігурації. Щоб агент навіть не пробував Bash, приберіть його з контексту через tools=[].
6. Треба перевірити, що відхилена цитата доходить до моделі як tool_result з is_error: true і правильним tool_use_id. Як це зробити найдешевше й надійно?
Так. Фейк детермінований, працює без мережі й показує, що саме цикл надіслав би моделі на третьому запиті.
Справжня модель недетермінована й коштує грошей, а тест інструмента не доводить, що цикл правильно упакує його помилку. Перевіряти треба шов між ними.
7. У прогоні 4 перший save_quiz пройшов, хоча містив «Дві треті��и», і агент на SDK сам зберіг квіз ще раз. Що сталося б у шляху A до виправлення?
Так. Шлях A повертає результат одразу після save_quiz, тож шансу перечитати в моделі немає. Захист — правило U+FFFD у validate(), там, де цикл зупиняється.
strict гарантує форму JSON, а не вміст рядка: U+FFFD — цілком валідний символ. Фінальний текст після збереження пише лише шлях B, а його друге збереження — щасливий випадок, а не властивість системи.
8. Чому closest_sentence береться з оригінального тексту, а не з norm(text), якщо порівняння однаково нормалізоване?
Так. Прогін 3: «а кортеж - може» замість «—». Цитата пройшла лише нормалізоване порівняння, а в квізі стояв не той символ, що в лекції.
Нормалізована підказка якраз проходить повторну перевірку — тому помилка й дійшла до квізу. Швидкість тут ні до чого: нормалізація потрібна для порівняння, а все, що модель побачить і скопіює, має бути оригіналом.
9. Сервіс генерує квізи для тисяч лекцій. Потрібні аудит кожного запиту, власна стратегія кешу й легкий контейнер. Що обрати?
Так. Тут цикл — частина продукту: потрібні контроль запитів і кешу, без підпроцесу і 238 МБ бінарника.
SDK вигідний, коли потрібні вбудовані інструменти, дозволи, хуки й сесії; його кеш і оцінка вартості — не ваші, а контейнер важчає на 238 МБ. Headless CLI у циклі має ті самі обмеження, що й SDK, і до них ще парсинг виводу.
10. Ви запускаєте Lectern-промпт через agent -p --output-format json у Cursor CLI. Як гарантувати, що квіз відповідає схемі?
Так. У документації Cursor CLI немає параметра для схеми. json лише обгортає відповідь, а форму тексту задає промпт.
--output-schema — параметр Codex, у Cursor CLI його немає. --output-format json — це конверт навколо результату, а не перевірка вмісту: схема в промпті лише просить, а не гарантує.
11. Handler інструмента в SDK кинув KeyError, бо модель передала аргумент з іншим ім'ям. Що станеться?
Так. Агент не падає, але модель отримує лише «KeyError: 'quote'». Тому Session.call сам перехоплює такі помилки й пише, що саме не так з аргументами.
Виняток в in-process інструменті не зупиняє цикл: модель бачить його як результат з помилкою, і в ньому сирий текст винятку. Від вас залежить лише, наскільки зрозумілим буде повідомлення.
