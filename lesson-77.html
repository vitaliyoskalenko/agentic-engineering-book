Що насправді перевіряютьЗнання, судження чи руки

Один і той самий бал на різних іспитах означає різні речі. Розрізняйте три типи питань: знання («що робить сервіс X»), судження (сценарій з обмеженнями, де треба обрати компроміс) і руки (виконати задачу в справжньому середовищі). Жоден із цих іспитів не має практичної частини: усі складаються з питань з вибором.

Що каже мапа

Половину, яку закриває курс, вендори формулюють своїми словами: chunking, guardrails, evals, MCP, вибір моделі за вартістю й латентністю. Решта — предметний словник платформи: сервіс, налаштування адмінки, параметр API. Його не виводять з принципів, а вчать — цільовим проходом документацією за доменами з найбільшою непокритою вагою.

Приклади питань у стилі іспиту

1 · Агент прочитав виключений файл

Організація виключила каталог secrets/ через content exclusion. Розробниця в VS Code просить Copilot в agent mode «знайти, де читається конфіг», і агент відкриває файл із secrets/. Чому?

  1. Зміни політики ще не доїхали до клієнта: треба перезапустити IDE.
  2. Content exclusion не підтримується в режимах Edit і Agent у Copilot Chat у VS Code та інших редакторах.
  3. Каталог є символьним посиланням, а виключення на symlinks не діють.
  4. Виключення налаштував власник репозиторію, а діє лише налаштування власника організації.

Відповідь: B. Документація GitHub прямо називає Edit і Agent mode винятками. C — справжнє обмеження, але про symlink в умові нічого немає; D хибне: виключення задає й адміністратор репозиторію. Виключення з контексту — не межа доступу (урок 3.4): хто має shell, той його обійде, і в Cursor (.cursorignore), і в Claude Code (deny для Read без sandbox).

2 · Юрист проти збігів із публічним кодом

Юридичний відділ вимагає: Copilot не повинен пропонувати код, що збігається з публічним. Що налаштувати?

  1. Content exclusion для всіх публічних репозиторіїв організації.
  2. Рядок у .github/copilot-instructions.md: «не копіюй публічний код».
  3. Політику «suggestions matching public code» у режимі Block на рівні організації.
  4. Перегляд подій audit log раз на тиждень.

Відповідь: C. Content exclusion керує входом, а не виходом; інструкція — побажання моделі, а не гарантія; audit log лише фіксує. Якщо збіги дозволено або продукт не підтримує Block, Copilot показує code references.

3 · Copilot CLI у CI з найменшими правами

Нічний job має попросити Copilot CLI підсумувати коміти тижня. Агент повинен запускати лише git. Яка команда?

  1. copilot -p "…" --allow-all-tools
  2. copilot -p "…" --allow-tool='shell(git)'
  3. copilot в інтерактивному режимі з ручним підтвердженням
  4. copilot -p "…" без прапорців — CLI сам відмовиться від небезпечних команд

Відповідь: B. -p — програмний режим, --allow-tool — точковий дозвіл. A дає агентові будь-яку команду, у C в CI нікому підтверджувати, а в D агент не отримає права на shell: документація вимагає для запуску команд одну з approval-опцій. Це той самий принцип, що --allowedTools "Bash(git *)" у claude -p (урок 4.4).

  • Unity Catalog: Delta-таблиці для фрагментів, реєстрація моделі через MLflow;
  • Mosaic AI Vector Search: створення, запити, конфігурація під обсяг, частоту оновлень і латентність;
  • Model Serving, Foundation Model APIs, контроль доступу до endpoint;
  • MLflow і Agent Framework, pyfunc з pre- і post-processing, scorers;
  • ai_query() для пакетного інференсу, inference tables, AI Gateway, Agent Monitoring;
  • Agent Bricks, Genie Spaces, Databricks Apps.

Мінімальний добір (наша оцінка — 25–35 годин, з них половина практики): exam guide з розділом AI Prep Guide (промпт, що генерує 6–10 практичних задач під цілі іспиту); Databricks Free Edition — гайд пише, що кожна задача вміщається в неї; self-paced курси в Databricks Academy: Building RAG Agents with Agent Bricks, Building Agentic Applications on Databricks, Agent Evaluation on Databricks, Deploying and Monitoring Agent Applications on Databricks.

Приклади питань у стилі іспиту

1 · Колонтитули в індексі

RAG над 300-сторінковими регламентами відповідає «Конфіденційно. Сторінка 14 з 300» на питання про відпустки: у top-5 потрапляють фрагменти з колонтитулами. Що зробити насамперед?

  1. Збільшити top-k до 20, щоб корисні фрагменти теж потрапили в контекст.
  2. Прибрати повторювані колонтитули й службові блоки до chunking і переіндексувати.
  3. Перейти на embedding-модель з довшим контекстом.
  4. Додати reranker поверх наявного пошуку.

Відповідь: B. Ціль гайда — «filter extraneous content that degrades quality». Шум з кожної сторінки заходить у кожен фрагмент і зсуває всі вектори. A розбавить контекст, C не прибере шуму, D пересортує ті самі забруднені фрагменти (урок 9.2).

2 · Два мільйони рядків щоночі

Щоночі треба стиснути 2 млн звернень з Delta-таблиці до одного речення кожне. Латентність окремого запиту неважлива, важливі пропускна здатність і простота. Що обрати?

  1. Python-цикл, що викликає real-time endpoint Model Serving для кожного рядка.
  2. Пакетний інференс SQL-функцією ai_query() над таблицею з моделлю, оптимізованою для batch.
  3. Агента з інструментом читання таблиці, який сам обробить рядки.
  4. Fine-tuning меншої моделі перед кожним запуском.

Відповідь: B. Ціль гайда — «identify batch inference workloads and apply ai_query() appropriately». A платить латентністю й ретраями за кожен рядок, C ставить агента туди, де кроки відомі заздалегідь (урок 2.4), D розв'язує не ту проблему.

Приклади питань у стилі іспиту

AIF · 1 · Шахрайство в 1% транзакцій

Модель виявляє шахрайство; шахрайських транзакцій близько 1%, пропущене шахрайство коштує в сотні разів дорожче за зайву перевірку. Яку метрику тримати головною?

  1. Accuracy — частку правильних відповідей.
  2. Recall — частку знайдених шахрайств серед усіх.
  3. Середню латентність відповіді моделі.
  4. ROI проєкту за квартал.

Відповідь: B. Модель, що завжди каже «не шахрайство», має accuracy 99% і нуль користі. Ціна пропуску визначає метрику (урок 9.5); словник precision/recall/F1 — прогалина домену 1.

AIF · 2 · Регламенти, що змінюються щомісяця

Чат-бот має відповідати за внутрішніми регламентами й посилатися на чинну редакцію; регламенти оновлюються щомісяця. Що найпростіше?

  1. Щомісяця донавчати модель на нових регламентах.
  2. RAG над регламентами — на AWS через Amazon Bedrock Knowledge Bases.
  3. Pre-training власної моделі на корпусі компанії.
  4. Обрати модель з найбільшим контекстним вікном і вставляти всі регламенти в кожен запит.

Відповідь: B. Свіжість і посилання на джерело — аргументи за retrieval (урок 5.3): ваги не скажуть, з якої редакції відповідь. D може спрацювати на малому корпусі, але не дасть посилань на чинну редакцію.

AIP · 1 · Агент передає в інструмент сміття

Агент на Strands Agents інколи викликає інструмент оформлення повернення з порожнім order_id, і помилка спливає в іншому сервісі. Що зробити?

  1. Знизити temperature до 0, щоб виклики стали детермінованими.
  2. Перевіряти параметри в самому інструменті (наприклад, у Lambda) і повертати моделі структуровану помилку, яку вона може виправити.
  3. Перейти на більшу модель: вона рідше помиляється в параметрах.
  4. Додати в системний промпт три приклади правильного виклику.

Відповідь: B. Навик 2.1.6 гайда — Lambda-функції для обробки помилок і валідації параметрів. Детермінізм не робить виклик правильним, а промпт і модель лише знижують частоту помилки. Інструмент сам захищає свій контракт (урок 7.4).

AIP · 2 · PII у відповідях

Асистент підтримки інколи повторює у відповіді номер картки чи адресу клієнта. Треба маскувати PII і на вході, і на виході з мінімумом власного коду. Що обрати?

  1. Інструкцію в системному промпті «ніколи не виводь персональні дані».
  2. Amazon Bedrock Guardrails із sensitive information filter у режимі маскування для запитів і відповідей.
  3. Логи всіх відповідей у CloudWatch і щотижневий ручний перегляд.
  4. Fine-tuning моделі на знеособлених діалогах.

Відповідь: B. Фільтр блокує або маскує PII в запитах і відповідях. A — побажання моделі, C знаходить витік після нього, D не прибирає PII, яку надіслав сам клієнт (урок 15.3).

10

Квіз12 питань

12 питань
1. У компанії Copilot Business — стандарт. Менеджер хоче сертифікат, який підтвердить, що команда користується ним безпечно і в межах політик. Що обрати?
Так. Відповідальне використання (15–20%), приватність і виключення (10–15%), політики організації в домені функцій — це рівно те, про що питає менеджер.
AIF-C01 і CCA-F не питають про content exclusion, політики організації GitHub чи audit log. Сертифікат про безпечне використання конкретного інструмента — вендорний: GH-300.
2. Ви пройшли цей курс і маєте два тижні до GH-300. На що піде більшість часу?
Так. Непокрита вага = вага × (1 − покриття): 27,5 × 0,7 ≈ 19 пунктів із 39 непокритих — майже половина всієї прогалини.
Промпти курс закриває майже повністю, а відповідальне використання — не найбільший домен (15–20% проти 25–30%). Час іде туди, де найбільша непокрита вага: функції, плани, CLI, адмінка.
3. Після інциденту CISO просить гарантію, що Copilot-агент у VS Code ніколи не прочитає config/prod.env. Що відповісти?
Так. Документація GitHub називає Edit і Agent mode винятками з content exclusion. Гарантію дає лише відсутність секрету там, куди дотягується агент.
Рівень, на якому задано виключення, нічого не змінює: в Agent mode у VS Code воно не діє взагалі. Інструкція — побажання моделі, а не контроль доступу.
4. У Claude Code стоїть deny для Read(./.env). Агент запускає python3 load.py, який сам відкриває .env. Що станеться?
Так. За документацією, deny для Read/Edit не поширюється на довільні підпроцеси, що відкривають файли самі. Межу на рівні ОС дає sandbox.
Claude Code не аналізує, які файли відкриє Python-скрипт, і нічого не підміняє. Правило діє на Read, Edit, упізнані команди на кшталт cat і перенаправлення — для решти потрібен sandbox.
5. Ви сильні в RAG і evals, але Databricks не відкривали. Чому розділ Assembling and Deploying (22%) — головний ризик?
Так. Механізми ви знаєте, а цілі розділу сформульовано через конкретні API платформи: курс закриває близько чверті ваги.
Найбільший розділ — Application Development (30%), а chunking — це Data Preparation. Ризик Assembling and Deploying у тому, що його цілі — це назви інструментів Databricks.
6. Для щотижневого регресійного прогону RAG-асистента треба вирішити, якому judge потрібні еталонні відповіді. Якому?
Так. Ціль Databricks «identify evaluation judges that require ground truth» — саме про це. Groundedness порівнює відповідь зі знайденими фрагментами.
Groundedness звіряє відповідь з контекстом, safety — з політикою; обом еталон не потрібен. Еталон потрібен лише correctness — тому golden set і дорогий (урок 12.3).
7. PM у компанії на AWS хоче говорити з інженерами однією мовою; коду не пише. Що обрати?
Так. Гайд AIF-C01 виносить за межі розробку моделей і пайплайнів і описує кандидата як того, хто «uses, but does not necessarily build».
AIP-C01 — сценарії продакшн-розробки на 180 хвилин, без досвіду це вгадування. Databricks прив'язаний до платформи не менше за інших і до того ж не AWS.
8. На пробному AIP-C01 ви слабкі в домені 5 (11%), решта — сильні. Чи можна скласти?
Так. AWS прямо пише: проходити кожен розділ не потрібно. Але 11% ваги — це близько семи оцінюваних питань, тож краще закрити прогалину.
AWS оцінює компенсаторно: розділи не мають окремих порогів. Неоцінювані питання на іспиті не позначені, тож ставити на них не можна.
9. Ваш AIF-C01 спливає за рік, і ви плануєте складати AIP-C01. Як поновити AIF-C01?
Так. Сторінка recertification AWS називає складання AIP-C01 одним із трьох способів поновити AI Practitioner — ще на три роки.
Безкоштовна онлайн-оцінка — механізм Microsoft (AI-103 поновлюють щороку). AIF-C01 діє три роки; його поновлює нова версія AIF-C01, ML Engineer – Associate або AIP-C01.
10. Кандидат має GH-300 і AIP-C01. Що це доводить напевно?
Так. Досвід у гайдах лише рекомендований, практичної частини немає. Що він уміє, покаже його репозиторій і розмова про конкретний інцидент.
Рекомендований досвід ніхто не перевіряє, а evals і бюджети на цих іспитах перевіряють питаннями з вибором. AWS для практики має окремі кредити «Demonstrated».
11. Lectern-агент на Agent SDK треба запускати через Amazon Bedrock. Що міняємо?
Так. Quickstart Agent SDK називає цю змінну й облікові дані AWS як спосіб перемкнути провайдера. Модель краще закріпити явно — документація радить для хмарних провайдерів pinning версій.
Agent SDK підтримує Bedrock, Claude Platform on AWS, Agent Platform і Foundry через змінні оточення. Переписувати агента не треба — це конфігурація, а не код.
12. Команда тримає CLAUDE.md у корені; частина людей працює в Copilot. Що Copilot зробить з цим файлом?
Так. Серед agent instructions GitHub називає найближчий AGENTS.md або один CLAUDE.md чи GEMINI.md у корені — спільний контекст можна тримати в одному файлі (урок 13.1).
Окрім copilot-instructions.md, Copilot підтримує path-specific *.instructions.md і agent instructions — AGENTS.md або CLAUDE.md. Політики організації — окремий механізм в адмінці.
